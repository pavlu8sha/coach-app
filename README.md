# Coach App

Веб-приложение для управления футбольной школой: игроки, группы, посещаемость, абонементы и платежи, дополнительные и индивидуальные занятия, экипировка и административные операции.

## Источник истины

- **`master`** — основная стабильная ветка исходного кода.
- **GitHub Issues** — задачи, дефекты и решения, которые ещё нужно принять.
- **Pull Requests (PR)** — единственный штатный путь внесения изменений в `master`.
- **Google Apps Script deployment** — отдельный этап. Слияние в `master` само по себе не означает публикацию в production.

Текущий статус работ: [docs/PROJECT_STATUS.md](docs/PROJECT_STATUS.md). Принятые правила и важные решения: [docs/DECISIONS.md](docs/DECISIONS.md). Роли агентов и передача задач: [docs/AGENT_WORKFLOW.md](docs/AGENT_WORKFLOW.md).

## Технологии и тесты

- Google Apps Script (HTML Service + server-side JavaScript).
- Автоматические Node.js-тесты находятся в каталоге `tests/`.
- Workflow CI, подготовленный в PR #3, запускает `node --test tests/*.mjs` для pull request в `master` и push в `master`.

Тесты с моками и GitHub Actions не должны изменять боевые таблицы. Не запускайте экспериментальные операции записи через production Apps Script.

## Рабочий процесс

1. Перед началом работы обновить `master` и проверить открытые Issues/PR.
2. На одну логически связанную задачу — отдельная ветка и PR.
3. Не работать одновременно над одной областью в нескольких ветках без явного согласования.
4. PR должен описывать причину, изменения, риски, тесты и влияние на deployment.
5. Не вливать PR, пока обязательные проверки не пройдены и замечания не закрыты.
6. После слияния отдельно отметить, был ли код опубликован в Apps Script и как проверен.
7. Не удалять старые ветки, пока не проверены уникальные коммиты и сохранность нужных изменений.

Подробные правила: [CONTRIBUTING.md](CONTRIBUTING.md).
