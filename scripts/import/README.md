# Импорт из таблиц в базу

Таблицы не читаются напрямую: владелец экспортирует нужный лист в CSV (Файл → Скачать → CSV), скрипт читает файл.

## Реестр игроков

1. Экспортируйте лист «РЕЕСТР ИГРОКОВ» в CSV.
2. Проверка без записи: `node scripts/import/run-players.mjs registry.csv`
3. Запись (сначала на тестовом проекте): задайте `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `CLUB_ID` и запустите с `--write`.

Скрипт не пишет, если есть строки с ошибками. Ключ сервиса — только в переменных окружения, в репозиторий не кладём.

## Отчёт о качестве данных

Только чтение, без аргументов:

```powershell
$env:SUPABASE_URL = "https://<project>.supabase.co"
$env:CLUB_ID = "<uuid клуба>"
$k = Read-Host "Ключ"; $env:SUPABASE_SERVICE_KEY = $k
node scripts/import/quality.mjs
```

Скрипт делает только `GET /rest/v1`, ключ `--write` запрещён. Сначала печатает таблицу проверок, затем детали (до 20 строк на проверку). Коды выхода: `0` — только замечания категории «гигиена», `1` — есть проблемы, влияющие на родителей или тренеров/администратора, `2` — отчёт не удалось построить.

Проверки: матчи и составы, активные игроки без групп, дубли ФИ, даты рождения, платежи и абонементы, цены групп, журнал баллов, занятия и посещаемость, расписание, тестовые согласия и связи родитель–ребёнок, запросы на связь, Telegram ID и привязки тренеров. Даты сравниваются по Тбилиси.

В схеме нет `groups.active` и `users.club_id`: проверка неактивных групп и администраторов вне клуба ограничена тем, что можно определить по имеющимся таблицам.

## Дополнительные тренировки

Старые данные лежат в листах `EXTRA_ID` (лист = дата `дд.мм`). Выгрузка всех листов в CSV: `migrationExport()` в Apps Script (папка `EXTRA_ID`). Из админ-файла по желанию взять листы «ДОПОЛНИТЕЛЬНЫЕ ТРЕНИРОВКИ» (суммы) и «ДОПОЛНИТЕЛЬНЫЕ ОПЛАТЫ» (способ и сумма оплаты).

1. Проверка без записи: `node scripts/import/run-extra.mjs --registry registry.csv --dir EXTRA_ID --prices "ДОПОЛНИТЕЛЬНЫЕ ТРЕНИРОВКИ.csv" --journal "ДОПОЛНИТЕЛЬНЫЕ ОПЛАТЫ.csv" --year 2026 --amount 20`
2. Запись: те же аргументы плюс `--write` и переменные `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `CLUB_ID`. Нужна миграция 0035. Повторный запуск не дублирует.

Года в названии листа нет: он берётся из `--year`, а дата далеко в будущем относится к прошлому году. Если в листах есть данные за несколько лет, запускайте по годам.
