# Условия приёмки: резервные копии боевой БД (REL-01)

Тесты пишутся от этих условий: `tests/ops/backup-scripts.test.mjs` (статические и отказы до подключения) и `tests/ops/backup-integration.test.mjs` (локальный PostgreSQL, в CI в задаче db). Против боевой БД ничего не запускается: проверки статические и локальные.

1. **Секреты не в репозитории.** Строка подключения к Supabase читается из переменной `SUPABASE_DB_URL` или из файла вне репозитория (`~/.config/kickstart/backup.env`, права 600). В скриптах и документах нет строк `postgresql://user:пароль@…`.
2. **Каталог копий вне репозитория.** Скрипт отказывается писать внутрь рабочей копии git.
3. **Версия клиента совпадает с сервером.** Скрипт сравнивает мажорную версию `pg_dump` и сервера и останавливается при расхождении.
4. **Формат и целостность.** Дамп в custom-формате (`pg_dump -Fc`), рядом `*.sha256` и `*.manifest` (число строк по всем таблицам `public`). Сразу после записи `pg_restore -l` должен читать файл.
5. **Шифрование обязательно, без исключений.** Без `AGE_RECIPIENT` в формате age (`age1` и 58 символов) скрипт не пишет дамп. Любое значение `ALLOW_PLAIN` (в окружении или в backup.env) останавливает скрипт до подключения к базе. Открытый дамп пишется только во временную папку с правами 700 и удаляется при любом выходе; в каталог копий попадают только файлы age, через переименование готового файла. При сбое age копия не записывается и открытого дампа на диске не остаётся (замечание к PR #621).
6. **Ротация.** Ежедневные копии: 14 дней. Недельные (воскресные): 8 недель. Копии перед миграцией (`BACKUP_KIND=premigration`) ротацией не удаляются.
7. **Проверка восстановления.** Принимает только `.dump.age`. Каждый запуск создаёт новую базу `kickstart_restore_check_<время>_<случайное>` без `drop if exists`; занятое имя — ошибка. Удаляется только база этого запуска с его меткой в комментарии, в том числе при сбое; существующие базы (включая `kickstart_restore_check`) не трогаются (замечание к PR #621). `backup-restore-check.sh` поднимает дамп в отдельной локальной БД PostgreSQL (не Supabase, адрес с `supabase.co` отвергается), создаёт роли `anon`, `authenticated`, `service_role` как в Supabase, восстанавливает, сверяет число строк с manifest и запускает `db/ops/preflight.sql`. Любая ошибка восстановления или расхождение счётчиков дают ненулевой код выхода.
8. **Сверка без записи.** `backup-manifest-counts.sql` только читает (`select`), без DML/DDL.
9. **Документ.** `db/ops/BACKUP.md` описывает расписание, хранение, восстановление, что дампом не покрыто (файлы Storage, Edge Functions, секреты, Google Sheets старого приложения), и правило «перед миграцией — свежая копия».
10. **Ничего не применяется.** Скрипты не меняют схему и данные ни в одной базе, кроме локальной проверочной.
