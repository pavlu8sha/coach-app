# Условия приёмки: резервные копии боевой БД (REL-01)

Тесты пишутся от этих условий (`tests/ops/backup-scripts.test.mjs`). Против боевой БД ничего не запускается: проверки статические и локальные.

1. **Секреты не в репозитории.** Строка подключения к Supabase читается из переменной `SUPABASE_DB_URL` или из файла вне репозитория (`~/.config/kickstart/backup.env`, права 600). В скриптах и документах нет строк `postgresql://user:пароль@…`.
2. **Каталог копий вне репозитория.** Скрипт отказывается писать внутрь рабочей копии git.
3. **Версия клиента совпадает с сервером.** Скрипт сравнивает мажорную версию `pg_dump` и сервера и останавливается при расхождении.
4. **Формат и целостность.** Дамп в custom-формате (`pg_dump -Fc`), рядом `*.sha256` и `*.manifest` (число строк по всем таблицам `public`). Сразу после записи `pg_restore -l` должен читать файл.
5. **Шифрование обязательно.** Без `AGE_RECIPIENT` скрипт не пишет дамп (кроме явного `ALLOW_PLAIN=1` для локальной отладки). Дамп содержит данные детей и платежи.
6. **Ротация.** Ежедневные копии: 14 дней. Недельные (воскресные): 8 недель. Копии перед миграцией (`BACKUP_KIND=premigration`) ротацией не удаляются.
7. **Проверка восстановления.** `backup-restore-check.sh` поднимает дамп в отдельной локальной БД PostgreSQL (не Supabase, адрес с `supabase.co` отвергается), создаёт роли `anon`, `authenticated`, `service_role` как в Supabase, восстанавливает, сверяет число строк с manifest и запускает `db/ops/preflight.sql`. Любая ошибка восстановления или расхождение счётчиков дают ненулевой код выхода.
8. **Сверка без записи.** `backup-manifest-counts.sql` только читает (`select`), без DML/DDL.
9. **Документ.** `db/ops/BACKUP.md` описывает расписание, хранение, восстановление, что дампом не покрыто (файлы Storage, Edge Functions, секреты, Google Sheets старого приложения), и правило «перед миграцией — свежая копия».
10. **Ничего не применяется.** Скрипты не меняют схему и данные ни в одной базе, кроме локальной проверочной.
