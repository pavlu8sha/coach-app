# B2. Управление шаблонами индивидуальных тренировок (Issue #598)

## Цель

Администратор управляет шаблонами индивидуальных и вратарских тренировок из приложения: создаёт, меняет день недели, начало, окончание и тип, включает и отключает шаблон. Шаблоны остаются единственным источником для автосоздания занятий; отдельной системы шаблонов нет.

## Границы

- Не меняются правила записи родителей, расписание открытия записи, вместимость, общий выключатель записи.
- Не меняется алгоритм автосоздания занятий, кроме чтения флага `active`.
- Существующие занятия, записи, платежи, посещаемость и постоянные игроки не удаляются и не переписываются.
- Физическое удаление шаблона через API запрещено; отключение выполняется через `active = false`.
- Все проверки выполняются без production-миграций, backfill, деплоя и изменения production-данных.

## Условия приёмки

### Права

1. Создавать, изменять и отключать шаблоны может только администратор.
2. Неадминистратор не может создать шаблон прямым запросом к API/БД.
3. Неадминистратор не может изменить день, время, тип или `active` существующего шаблона прямым запросом.
4. Неадминистратор не может удалить шаблон прямым запросом.
5. Неадминистратор не видит шаблоны в списке; скрытие кнопок в UI не является защитой.

### Поля шаблона

6. День недели: целое число от 1 (понедельник) до 7 (воскресенье).
7. Время начала обязательно.
8. Окончание необязательно; если задано, оно строго позже начала.
9. Тип: «Индивидуальные» или «Вратари».
10. Шаблон можно создать сразу активным или отключённым.
11. Дубликат по клубу, дню, времени начала и типу отклоняется с понятным сообщением, в том числе если существующий шаблон отключён.

### Создание и правка

12. Администратор создаёт шаблон с днём, началом, необязательным окончанием, типом и признаком активности.
13. Администратор меняет у существующего шаблона день, начало, окончание, тип и активность.
14. После сохранения список показывает новые значения без перезагрузки страницы.
15. Ошибки валидации показываются рядом с формой; неверные данные не записываются.
16. Ошибки БД (дубликат, ограничение времени, недостаточно прав, отсутствие миграции) показываются понятным текстом.

### Отключение и история

17. Отключение не удаляет шаблон физически.
18. Отключённый шаблон не создаёт новые занятия при следующем автосоздании.
19. После отключения прошедшие занятия, записи, платежи и постоянные игроки остаются без изменений.
20. Включение отключённого шаблона снова разрешает автосоздание будущих занятий.
21. Физическое удаление шаблона через API запрещено даже администратору; история и связи сохраняются.

### Совместимость

22. Существующие шаблоны и их поля читаются без изменений.
23. Автосоздание по активному шаблону продолжает работать.
24. Экран «Постоянные» продолжает работать: активные шаблоны, постоянные игроки, переполнение и правка окончания.
25. Вкладки «Индивидуальные» и существующие сценарии занятий/оплат/долгов не меняются.

## Проверки

### pgTAP, `db/tests/rls_individual_templates_admin_test.sql`

- неадминистратор: вставка отклоняется, обновление/отключение/удаление не меняют данные, список пуст;
- администратор: создание и правка проходят;
- день вне 1–7, окончание не позже начала, пустое начало и дубликат отклоняются ограничениями БД;
- администратор не может удалить шаблон через API;
- после отключения шаблон существует с `active = false`;
- занятия, записи и постоянные игроки сохраняются;
- автосоздание создаёт занятие по активному шаблону и не создаёт по отключённому.

### Vitest, `web/src/screens/IndTemplates.test.tsx`

- список показывает активные и отключённые шаблоны;
- создание отправляет правильные поля и `club_id`;
- правка отправляет изменённые день, время, тип и активность;
- отключение требует подтверждения и отправляет `active = false`;
- включение отправляет `active = true`;
- окончание не позже начала и пустое начало не записываются;
- дубликат и ошибка прав показываются понятным текстом.
