# Реестр аудитов Coach App

- **Назначение:** единый указатель на аудиты, их исходные отчёты, находки и последующие решения.
- **Актуальность реестра:** 19.11.2026.
- **Репозиторий:** `pavlu8sha/coach-app`.
- **Снимок master при составлении:** `871820b7c6fa48584cbe0e7407c180775b9e3052`.
- **Правило:** реестр не заменяет подробные отчёты и Issues. Он связывает источники и показывает жизненный цикл находок. Если отчёт существует только в чате/комментарии, это явно отмечается — нельзя считать его перенесённым в документацию.

## Как читать статусы

- **Аудит завершён** — проверка и отчёт представлены.
- **Нужны решения** — есть находки, требующие решения владельца или уточнения требований.
- **В работе** — аудит ещё не завершён.
- **Реализация отдельно** — аудит завершён, дальнейшая работа ведётся в отдельных Issues/PR.
- **Не подтверждено** — вывод/проверка не подтверждены актуальным источником; не трактовать как пройденную проверку.
- **Проверка после исправления** — отдельная проверка должна подтвердить устранение дефекта; факт наличия PR или merge сам по себе этого не доказывает.

## Правила ведения реестра

1. Новый аудит добавляется сюда только после появления проверяемого источника: документа, Issue/PR с отчётом или зафиксированного комментария.
2. Для каждого аудита записывать исполнителя, дату, base SHA (если применимо), область и ограничения метода.
3. Находки связывать с Issues/PR; не копировать сюда полные описания дефектов.
4. Статусы находок вести по фактическим доказательствам: обнаружено → подтверждено → задача создана → исправлено → проверено после исправления. Merge не равен проверке исправления.
5. Отдельно отмечать остаточные риски, непроверенные области и отсутствие доступа/среды.
6. Перед созданием новой Issue искать существующие задачи и проверять актуальный код.
7. Не запускать production-проверки, SQL, миграции, backfill, deploy, clasp push или реальные уведомления без отдельного разрешения владельца.
8. При каждом существенном изменении статуса обновлять эту запись в рамках соответствующего docs PR или задачи; не создавать новый документ на каждый аудит.

## Ограничения текущего реестра

Это первый сводный индекс по доступным на 17.11.2026 документам, Issues, PR и переданным отчётам. Он не утверждает, что восстановлены абсолютно все устные/чатовые обсуждения или все исторические замечания OpenCode. Записи с пометкой «отдельного файла не найдено» требуют последующего переноса исходного отчёта в репозиторий, если он доступен. Неизвестные результаты не трактуются как успешные проверки.
