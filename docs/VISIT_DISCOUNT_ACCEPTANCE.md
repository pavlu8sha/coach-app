# Скидка на доп. посещение и закрытие без оплаты: условия приёмки

Файл написан до тестов и кода. Просьба Павла 23.11.2026: в Кассе («Игроки» → игрок → «Доп. посещения») дать скидку на доп. посещение чужой группы, в том числе закрыть его без оплаты, по аналогии с закрытием без оплаты у абонементов, взносов матчей и событий (причина обязательна, автор и дата сохраняются). Вид «Оплата за визит» (own_visits) в этой работе не меняется.

1. Скидку на доп. посещение (`session_guests`, 0178) ставит только глобальный администратор: функция `session_guest_discount(s, p, due, why)`. Тренеру, родителю и анониму отказ `42501` (`forbidden`); прямая запись в таблицу вошедшим пользователям по-прежнему закрыта.
2. Причина обязательна (не короче 3 символов после обрезки пробелов), иначе `22023` (`discount needs reason`). Новая сумма `due` не пустая и не отрицательная, иначе `22023` (`bad amount`).
3. Скидка действует только на неоплаченное посещение. Для оплаченного (`paid = true`, включая уже закрытое без оплаты) отказ `22023` (`visit paid`). Для несуществующего посещения `P0002`.
4. `due` больше 0 и меньше текущей суммы: сумма посещения (`amount`) становится равной `due`, посещение остаётся неоплаченным, долг уменьшается до `due`. `due` больше текущей суммы отклоняется (`22023`, `bad amount`): увеличить долг скидкой нельзя, сумма и журнал не меняются.
5. `due` равна 0: посещение закрывается без оплаты: `paid = true`, `paid_amount = 0`, способ пустой; в журнале платежей (`service_payments`) записей не появляется, касса и выручка не меняются; сумма посещения (`amount`) не меняется, долг игрока исчезает.
6. Одинаковая сумма (`due` равна текущей `amount`) ничего не меняет и не пишет в журнал.
7. Каждое изменение пишется в `fee_discount_log` (вид `visit`, `ref_id` = занятие, игрок, было, стало, причина, автор, время); журнал только дописывается, читает администратор.
8. Закрытое без оплаты посещение возвращается в долг существующей отменой оплаты (`session_guest_set_paid(..., false)`, только администратор): платежей для сторно нет, сумма посещения осталась прежней, поэтому посещение снова видно в Кассе с прежним долгом. Из экрана Кассы отмена закрытия без оплаты не вызывается (отдельная кнопка не входит в эту работу); при необходимости её делает администратор в «Отметках» или запросом.
9. Экран «Касса» (карточка «Доп. посещение»): кнопка «Скидка или закрыть без оплаты». Окно: причина (обязательна) и вид «Закрыть без оплаты» или «Скидка» с суммой к оплате; подтверждение, ошибка показывается человеческим текстом; после успеха список долгов обновляется, сообщение «Скидка применена» или «Посещение закрыто без оплаты». Остальные виды долгов (абонемент, экипировка, сборы, матчи, события, оплата за визит) эту кнопку не получают.
10. Дата и способ оплаты для закрытия без оплаты не нужны и не отправляются; обычная оплата доп. посещения работает как раньше.
11. Права проверяются на базе с привилегиями по умолчанию Supabase: `anon` не может вызвать функцию, `authenticated` может, а внутри проверка администратора; функция внесена в список функций, доступных вошедшим пользователям (`rls_definer_hardening_test.sql`).
12. Баллы и расписание не меняются: изменение `session_guests` не должно ломать пересчёт баллов (триггер 0178 срабатывает как раньше).
13. Откат: `db/ops/rollback-0221-visit-discount.sql` (функция удаляется, журнал остаётся). Применяет Павел после `db/ops/preflight.sql`.
