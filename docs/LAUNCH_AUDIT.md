## 3. Риски

1. **Двойная запись и сверка.** Пока Apps Script работает, тренеры пишут в таблицы. Нужен ежедневный скрипт сверки «таблица → база» на время переходного периода, иначе расхождения копятся (например, уже были расхождения по индивидуальным: Razorenov, Matrosov, Dzidziguri).
2. **Старые глобальные функции Apps Script** доступны через `google.script.run` (см. `docs/PROJECT_STATUS.md`). Пока приложение работает, это открытый риск безопасности.
3. **Персональные данные детей.** Телефоны, даты рождения, ФИО. Без юридической проверки и согласия запускать нельзя.
4. **Тестовой среды нет.** Все проверки идут по боевой базе Kickstart. Миграции и импорты сначала проверяются на чистой локальной базе (`/tmp/mexp/pgtest.sh`), запись только после «да» владельца.

## 4. Минимум для запуска в Telegram Mini App (MVP)

1. Миграции 0001–0010 применены в Kickstart; данные сверены (`verify.mjs`).
2. Edge Function входа через Telegram, тест на подделанный `initData`.
3. Связь родитель ↔ игрок (процесс и экран подтверждения админом).
4. SPA: три экрана — «мой ребёнок» (динамика, достижения), «группа» (групповой рейтинг), «настройки» (переключатель публичного рейтинга).
5. Посещаемость и правила баллов: импорт журнала или старт с нового сезона (решение владельца).
6. pgTAP-тесты RLS: родитель видит только своих детей, тренер только свои группы, персональные колонки только админу.
7. Текст согласия: черновик и механизм готовы (docs/CONSENT.md), нужна юридическая проверка; экспорт и удаление по запросу не сделаны.
8. Хостинг с HTTPS, домен, бот с Mini App URL в BotFather.
9. Пилот на одной группе, параллельно с таблицами, затем переключение чтения.

6. Срок параллельной работы с Apps Script и критерий переключения.

## 7. Идеи на будущее (не для запуска)

- **Уведомления в Telegram.** Сообщение администратору, когда родитель отправил запрос на связь с ребёнком, и сообщение родителю, когда связь подтверждена или отклонена. Нужен бот (токен уже есть в секретах функции входа) и отправка по событию из базы: Edge Function по вебхуку на `link_requests` или после вызова `decide_link`. Учесть: родитель мог ни разу не писать боту, а бот может писать пользователю, только если тот запустил бота или открыл мини-приложение.
- **Кнопка отзыва согласия** в приложении (сейчас вручную через администратора).
- **Сузить чтение матчей.** Политика `matches_read` пускает любого вошедшего пользователя; нужно ограничить группами ребёнка, тренера и администратором (то же для `weekly_schedule_read`, `rules_read`).
