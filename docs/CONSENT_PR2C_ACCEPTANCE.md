# #238, PR 2c: условия приёмки (проверка согласия при выдаче уведомления из очереди)

Миграция 0176. Основание: решения владельца от 11.11.2026 и аудит `/mnt/project-files/consent-238/pr2c-audit-2026-11-11.md`. Тесты пишутся от этих условий, код после тестов.

## Границы
Меняется: `notifications` (столбец `player_ids`, состояние `skipped`), `claim_notifications`, функции постановки адресных сообщений, `camp_broadcast_list`, `camp_broadcast_results` (0172), экран журнала рассылок. Не меняется: `finish_notification`, `enqueue_to_admins`, `notify_link_request`, `notify_data_request`, `notify_coach_group`, `parent_access_ok`, `has_consent`, `supabase/functions/tg-notify/*`. Включение режимов, деплой, применение миграции и реальные отправки не входят.

## Классификация сообщений
- **Адресные** (`player_ids` заполнен): payment, bonus (`enqueue_to_guardians`); booking_* и первая волна (`booking_family_notice`); waitlist_offer, waitlist_moved; rsvp_* (`rsvp_notify_parent`, в том числе напоминания); camp_broadcast_reminder.
- **Общие** (`player_ids` NULL): camp_broadcast_info, camp_document; старые строки очереди.
- **Исключения** (всегда NULL, по модели согласий не подавляются): администраторам и тренерам; link_decided; data_request_done; гостевые (camp_application_decision, гость-владелец).

## Условия
- **У1.** Адресная строка выдаётся `claim_notifications` только если для её получателя `parent_access_ok(user_id, player_id)` истинно для каждого `player_id` из `player_ids`.
- **У2.** Хотя бы один ребёнок без согласия: строка не возвращается, получает `state = 'skipped'`, `last_error = 'consent'`. Сообщение подавляется целиком.
- **У3.** Подавленное сообщение не возвращается в очередь после восстановления согласия.
- **У4.** Проверка выполняется при каждом claim, включая повторные попытки (строки в `pending` после ошибки Telegram и после истечения закрепления).
- **У5.** Строки с `player_ids IS NULL` (общие и старые) проверке не подвергаются.
- **У6.** Режимы `off`/`test`/`all` определяет только `parent_access_ok`. При `off` отзыв старым `consent_revoked_at` после постановки подавляет строку.
- **У7.** Ошибка вычисления проверки для строки: строка не выдаётся и не отправляется; ошибка считается отдельным счётчиком (`consent_check_attempts`), не `attempts`; после трёх ошибок строка `failed` с `last_error = 'consent_check_error'`. Ошибка одной строки не блокирует остальные в пачке.
- **У8.** Постановка: адресные функции записывают `player_ids` получателя (только дети, о которых его сообщение). Отзыв до постановки: строка не создаётся (как в 0173).
- **У9.** Два родителя одного ребёнка проверяются независимо. Один родитель с несколькими детьми: по каждому ребёнку из сообщения.
- **У10.** Смешанная пачка (общие и адресные, один и тот же получатель): общие доставляются независимо от подавления адресных.
- **У11.** Подавленные строки считаются в дневных лимитах рассылок (`camp_broadcast_targets`, `camp_document`). Слоты `match_reminder_log` и `booking_notice_log` при подавлении не освобождаются.
- **У12.** `camp_broadcast_list` возвращает колонку `skipped`; `pending + sent + failed + skipped + cleared = recipients`. `camp_broadcast_results` отдаёт состояние `skipped`. Экран показывает «не отправлено: нет согласия» и сумму без расхождения.
- **У13.** Конкуренция: отзыв, зафиксированный до проверки в claim, не позволяет выдать строку; claim не пропускает строку, отзыв которой уже подтверждён (сценарий с двумя сессиями).
- **У14.** Права: `claim_notifications` выполняет только `service_role`; прав у `public/anon/authenticated` нет; сигнатура и возвращаемые поля `(id, telegram_id, text, buttons)` не меняются; новые столбцы недоступны `anon/authenticated`.
- **У15.** `notifications_pending` и порядок выдачи (рассылки после обычных, лимит 50) сохраняются.
- **У16.** Существующие тесты записи на тренировки, RSVP, ожидания, кэмпов и уведомлений проходят без изменений ожиданий.
- **У17.** Preflight содержит строку 0176 и предусловия 0173, 0175; откат `db/ops/rollback-0176-consent-claim.sql` возвращает определения 0170/0173/0175 и убирает новые объекты; проверка отката в тестовой БД.
- **У18.** Тест-страж: прямой `insert into notifications` с адресным видом без `player_ids` в известных функциях не допускается (по `pg_proc`). Реализован в `db/tests/notifications_addressed_guard_test.sql` (follow-up к #616): классификация прямых, косвенных и общих функций, проверка определений в `public`, регрессия на дефектных версиях.
- **У17а (follow-up).** `preflight.sql` показывает у строки 0176 колонку `note`: `applied` / `ready` / `blocked` (нет 0173 и/или 0175) / `inconsistent` (0176 есть, предусловий нет) / `ambiguous` (0176 применена частично) / `unknown` (NULL). Тест: `db/tests/preflight_0176_test.sql`; `scripts/run-db-tests.sh` требует `applied` на полной базе.

## Принятые ограничения
- Окно между успешным claim и ответом Telegram (секунды) не проверяется; Edge Function не меняется.
- Подавленное сообщение не повторяется и не уходит задним числом.

## Вне границ
Режимы `test`/`all` не включаются; шлюз и экраны согласий (PR 3); публикации (PR 4); уход и обезличивание (PR 5).
