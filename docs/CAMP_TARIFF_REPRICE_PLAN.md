# Цены сборов: пересчёт записанных и защита от повторения

Дата: 2026-11-12. Связано: PR #618 (Surami), PR #622 (исправленный update.sql), урок 2026-11-12 в CLAUDE.md.

## Что случилось

Сбор Winter Camp 2027 переехал в Surami, цены тарифов изменились («Футболист» 1500 → 1350, «Ребёнок + 2 родителя» 3500 → «Футболист + 2 родителя» 3100, «Ребёнок + 1 родитель» 2500 отключён). У уже записанных игроков осталась старая сумма.

Причина: сумма записи `camp_participants.amount` — снимок цены тарифа на момент записи. Ни `camp_tariff_save` (карточка сбора), ни прямой `update camp_tariffs` её не меняют. Скрипт `camp-surami-2027-update.sql` это прямо оставил («суммы уже записанных не меняются»), а сверки «сумма ≠ цене тарифа» не было, поэтому расхождение увидели только на экране.

## Готовые скрипты (запускает только Павел, по порядку)

1. `db/ops/camp-surami-2027-update.sql` (из PR #622): даты, место, тарифы. Сначала ПРОВЕРКА, потом ПРИМЕНЕНИЕ, потом ПРИМЕНЕНИЕ 2.
2. `db/ops/camp-surami-2027-reprice.sql`: пересчёт записанных по правилу Павла 12.11.
   - ПРОВЕРКА: тарифы и каждая запись «сейчас → после», внесено, переплата. Вывод сохранить в CSV: это снимок для отката.
   - ПРИМЕНЕНИЕ: «Футболист» остаётся, цена 1350; любой другой тариф → «Футболист + 2 родителя» 3100. Только `registered`. Внесено больше новой цены → запись не трогается, нужен возврат разницы, потом повторный запуск.
   - ОТКАТ: шаблон по сохранённому снимку.
3. `db/ops/readonly-camp-amount-vs-tariff.sql`: сверка по всем текущим сборам. После пересчёта должны остаться только переплаты.

Проверено на чистой БД со всеми миграциями master: лог `/mnt/project-files/camp-surami-reprice/test-run-2026-11-12.log`.

## Как не допустить повторения

Сразу, без кода:
- После любой смены цены или названия тарифа (в карточке сбора или SQL) запускать `readonly-camp-amount-vs-tariff.sql`. Пустой результат = всё сходится.
- Любой `db/ops`-скрипт, который меняет цены тарифов, обязан содержать блок пересчёта записанных или явно объяснять, почему суммы остаются, и заканчиваться сверкой.

В коде (предложение, ждёт решения Павла, потому что меняет финансовое правило):
- `camp_tariff_save` при смене цены пересчитывает записи `registered` на этом тарифе, у которых сумма равна старой цене (ручные суммы и скидки не трогаются), если внесено не больше новой цены. Возвращает: сколько пересчитано, сколько с переплатой, сколько с ручной суммой.
- Карточка сбора перед сохранением цены показывает: «у N записанных сумма станет X; у M внесено больше — нужен возврат; K с ручной суммой не изменятся». После сохранения: тот же итог.
- Родителю: новая сумма видна на экране «Мои сборы»; отдельное уведомление только через `camps.notify` (выключено, включает Павел).
- Тесты pgTAP: пересчёт по старой цене, ручная сумма не меняется, переплата пропускается, отменённые не трогаются, журнал пишет событие, права (только админ).
- Порядок по CLAUDE.md: файл условий приёмки → тесты → миграция (следующий свободный номер, сверить с master и открытыми PR) → строка в `db/ops/preflight.sql` → интерфейс.
