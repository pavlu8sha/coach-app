# Руководство по эксплуатации (2026-10-24)

Для владельца. Команды — для Windows (PowerShell). **Правило номер один:** при любом сомнении не трогайте боевую базу, а напишите разработчику (Claude Code). Все команды ниже безопасны, кроме тех, что помечены ⚠.

Связанные документы: `docs/OWNER_CHECKLIST.md` (что осталось сделать), `docs/NOTIFICATIONS.md`, `docs/DEBT_RULES.md`, `docs/DATA_REQUESTS.md`, `docs/CONSENT.md`, `docs/TRIGGERS_DEPLOY.md` (старое приложение).

## 1. Карта системы

| Что | Где | Как проверить, что живо |
|---|---|---|
| Приложение для родителей, тренеров, администратора | Cloudflare Pages, `https://coach-app-84b.pages.dev/` (сборка `web/` из `master`) | открыть адрес в браузере |
| База и права | Supabase, проект **Kickstart**, ref `ypxbwhjsqkrciozdhajf` | Supabase → Table Editor |
| Вход из Mini App | Edge Function `tg-auth` | открыть приложение из Telegram |
| Вход из браузера | Edge Function `tg-login` + виджет Telegram Login | открыть сайт в браузере |
| Рассылка уведомлений | Edge Function `tg-notify` + расписание `pg_cron` (раз в минуту) | `select state, count(*) from notifications group by 1;` |
| Бот: приветствие | Edge Function `tg-bot` (webhook) | написать боту `/start` |
| Старое приложение | Google Apps Script (корень репозитория), `clasp push` | отдельная инструкция: `docs/TRIGGERS_DEPLOY.md` |

**Публикация сайта автоматическая:** слияние в `master` запускает сборку Cloudflare. Слияние в `master` **не** публикует функции и **не** применяет миграции: это отдельные шаги (разделы 3 и 4).

## 2. Секреты и переменные (где лежат; значения никому не присылать)

| Название | Где задаётся | Для чего |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | секреты функций Supabase | подпись входа и отправка сообщений ботом |
| `TELEGRAM_WEBHOOK_SECRET` | секреты функций Supabase | защита webhook бота |
| `NOTIFY_SECRET` | секреты функций Supabase **и** в тексте расписания `cron` | защита запуска рассылки |

Если секрет мог попасть в чужие руки (в чат, скриншот, репозиторий): **немедленно замените его** (для токена бота: @BotFather → `/revoke` → новый токен → `npx.cmd supabase@latest secrets set TELEGRAM_BOT_TOKEN=…`), затем разверните функции заново (раздел 4).

## 3. Миграции базы

**Применяются только вручную, строго по порядку номеров.** Файл, который вы уже применили, повторно не применяют (часть миграций можно запускать повторно без вреда, но не рассчитывайте на это). Список применённых ведите у себя: в базе отдельного журнала миграций нет. Недавние миграции:

| Номер | Что делает |
|---|---|
| `0025_consent_controls` | отзыв согласия, выгрузка и запрос на удаление данных |
| `0026_notifications` | очередь уведомлений в Telegram |
| `0027_match_scoring_admin` | новая схема баллов за матч, лучший игрок, правки матчей администратором |
| `0028_child_access` | роль «Ребёнок» по коду |
| `0029_child_code_hardening` | криптостойкие коды и лимит попыток (после слияния его PR) |

Как применять:
1. Открыть файл миграции в GitHub (`db/migrations/<номер>.sql`) или получить текст от разработчика.
2. Supabase → SQL Editor → вставить **весь** текст → Run.
3. Предупреждение «destructive operations» при `drop`/`delete`/`update` ожидаемо, если в миграции они есть (разработчик отмечает это в описании).
4. Если Run вернул ошибку, **не запускайте остальное**: пришлите текст ошибки разработчику. Как правило, скрипт выполняется как одна транзакция и при ошибке не применяется частично, но убедиться в этом нужно проверочным запросом ниже.

Проверка, что функции установлены (только чтение; поменяйте список при необходимости):
```sql
select proname from pg_proc where pronamespace = 'public'::regnamespace
  and proname in ('open_session','mark_attendance','save_match','award_bonus','group_parents','parent_debts','debtors',
                  'revoke_consent','export_my_data','claim_notifications','recalc_match_points','create_child_code')
order by 1;
```

**Откат миграций автоматически не предусмотрен.** Для каждой миграции, которую писал Claude, в описании её PR есть «план отката» (какие `drop function`, политики вернуть). Предпочтительно **исправлять вперёд**: новая миграция с правкой, а не удаление прежней. Откатывать вручную без разработчика не стоит.

⚠ Выполнение запросов от имени администратора в SQL Editor: функции проверяют вход в приложение и отказывают `forbidden`. Если нужно вызвать такую функцию вручную, сначала в той же сессии: `select set_config('request.jwt.claims', json_build_object('sub', (select id from users where is_admin limit 1))::text, false);` Для пересчёта баллов есть кнопка в приложении («Ещё → Пересчёт баллов за матчи»).

## 5. Что делать при сбоях

### 5.1. Никто не может войти («Не получилось войти»)
1. Текст ошибки на экране: `rate_limited` / «Слишком много попыток» — подождать 10 минут (лимит 10 входов с аккаунта за 10 минут, 30 новых аккаунтов в час на клуб). Если вход закрыт у всех, смотрите шаг 3.
2. Supabase → Edge Functions → `tg-auth` → Logs: ищите `unauthorized`, `rate_limit`, `auth_create`.
3. Частая причина: токен бота сменили в BotFather, а секрет `TELEGRAM_BOT_TOKEN` не обновили. Обновить секрет и развернуть `tg-auth` и `tg-login`.
4. Лимитер недоступен → вход закрыт намеренно («закрыто по умолчанию»): проверить, что таблица `rate_limits` и функция `rate_limit_hit` на месте (миграция 0016).

### 5.2. Вход из браузера не работает
- Виджет не показывается: в BotFather `/setdomain` не указан домен сайта или не задана переменная `VITE_TG_BOT_USERNAME` (после изменения переменной нужна пересборка в Cloudflare).
- Виджет показывается, вход падает: развёрнута ли `tg-login`; логи функции.

### 5.3. Уведомления не приходят или идут лишние
- Очередь: `select state, count(*), max(created_at) from notifications group by 1;` — много `pending` значит отправитель не работает; много `failed` — получатели не запускали бота или заблокировали его (`select last_error, count(*) from notifications where state = 'failed' group by 1;`).
- Проверить расписание: `select jobname, schedule, active from cron.job;` (должна быть строка `tg-notify`), последние запуски: `select status, return_message, start_time from cron.job_run_details order by start_time desc limit 5;`.
- **Остановить рассылку немедленно:** `select cron.unschedule('tg-notify');` (возобновление — команда `cron.schedule` из `docs/NOTIFICATIONS.md`). Сообщения останутся в очереди.
- Отключить уведомления одному человеку: `update users set notifications_enabled = false where telegram_id = <id>;` ⚠.

### 5.4. Неверные баллы
- Ручной балл начислен по ошибке: «Ещё → Баллы игроков» → игрок → «Отменить» у начисления (автобаллы не отменяются, они пересчитываются отметками).
- Автобаллы за посещаемость: поправьте отметку в «Занятиях» (баллы пересчитаются сами).
- Автобаллы за матч: поправьте состав, голы или лучшего в «Матчах» или нажмите «Ещё → Пересчёт баллов за матчи».
- Матч внесён ошибочно: «Матчи» → матч → «Удалить матч» (администратор; удаляет и его баллы; с взносами не удаляется).

### 5.5. Неверный платёж
Платежи нельзя менять и удалять (даже администратору): «Ещё → Платежи» → игрок → «Исправить (записать с минусом)». Журнал сохраняет оба действия.

### 5.6. Неверный долг у родителя
1. **Сразу выключить показ долга родителям:** «Ещё → Должники» → «Выключить показ родителям» (либо SQL ⚠: `update club_settings set value = 'false' where key = 'parent_debt_enabled';`). Родители перестанут видеть «К оплате», остальное работает.
2. Сверить «Должники» за месяц со старым приложением; проверить цены («Ещё → Цены»), скидки, группу игрока (долг считается по группе).
3. Известное ограничение: платежи за месяц суммируются по всем программам игрока (`docs/DEBT_RULES.md`).

### 5.7. Родитель не видит матч, расписание или ребёнка
- Нет матчей: название группы и название команды в матче должны совпадать буквально (`matches.team` = `groups.name`). Проверьте в «Матчи» (администратор видит все команды).
- Нет ребёнка: связь не подтверждена («Запросы») или родитель отозвал согласие («Мои дети»).
- Нет расписания: у группы нет слотов («Ещё → Расписание»).

### 5.8. Нужно срочно закрыть приложение для всех родителей
Универсального выключателя в приложении нет. Варианты по скорости:
1. Cloudflare Pages → проект → **Deployments** → откат на предыдущий выпуск (если проблема в свежей версии сайта).
2. Cloudflare Pages → проект → Settings → Variables: временно очистить `VITE_SUPABASE_URL` и пересобрать: сайт покажет «Приложение не настроено». Потом вернуть значение и пересобрать.
3. Если подозревается утечка данных: заменить ключи (раздел 2) и написать разработчику; **не удаляйте** логи и `audit_log`.

### 5.9. Запрос родителя на удаление данных или отзыв согласия
Порядок и ограничения: `docs/DATA_REQUESTS.md` (администратор обрабатывает запросы во вкладке «Запросы»). Юридические сроки решает владелец.

## 6. Резервные копии

- Supabase → Project → **Database → Backups**. Какие копии и сколько хранятся, зависит от тарифа проекта: **проверьте это и запишите здесь** (в `docs/LAUNCH_AUDIT.md` вопрос «Бэкапы» помечен как открытый).
- Перед применением крупной миграции с `drop`/`update`/`delete` убедитесь, что свежая копия есть.
- Данные клуба, которые не лежат в базе: Google Таблицы старого приложения (хранятся у Google, версии файлов доступны в «История версий»).

## 7. Регулярные проверки (раз в неделю, 5 минут)

Все запросы только читают:
```sql
select state, count(*) from notifications group by 1;                       -- очередь уведомлений
select action, count(*), max(at) from audit_log group by 1 order by 3 desc;  -- что менялось: отзывы согласий, пересчёты, удаления
select count(*) from link_requests where status = 'pending';                 -- запросы, ждущие решения
select count(*) from data_requests where status = 'open';                    -- запросы на удаление данных
select key, hits, window_start from rate_limits order by window_start desc limit 10; -- нет ли всплесков входов
```
Дополнительно по расписанию (после PR OpenCode): `node scripts/import/verify.mjs "<папка выгрузки>"` (сверка с таблицами) и отчёт о качестве данных, если он будет добавлен.

## 8. Правила работы (напоминание)

- Запись в базу и слияние PR — только после вашего «да» / «сливай».
- Таблицы Google только читаем.
- Секреты в чат, в репозиторий и в скриншоты не попадают.
- Боевая база — единственная: тестовой среды нет, поэтому проверки делаются на временной локальной базе и в предпросмотрах.
