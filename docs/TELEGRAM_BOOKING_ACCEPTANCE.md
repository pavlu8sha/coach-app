# Запись на тренировку из Telegram-бота: условия приёмки (Issue #274)

Файл написан до тестов и кода. Тесты проверяют эти условия. Бот один: `@kicksapp` (Edge Function `tg-bot`), отдельного бота нет.

## Что делает родитель

1. В сообщении бота «Перед началом…» есть кнопка «Записаться на тренировку». Тот же пункт есть в ответе бота на обычный текст.
2. Список ближайших занятий (индивидуальные, вратарские, дополнительные), у которых есть хотя бы один подходящий ребёнок без записи. В строке видны дата, время, тип, цена и свободные места.
3. Выбор занятия → выбор ребёнка кнопкой (даже если ребёнок один). Для занятия без мест вместо записи предлагается отдельная кнопка «Встать в очередь».
4. Запись подтверждается всплывающим текстом «Запись подтверждена: <имя> — <занятие>». Кнопки под сообщением убираются, чтобы не нажать дважды.
5. Очередь ставится только по отдельному нажатию «Встать в очередь». Автоматически в очередь ничего не попадает.

## Правила (сервер решает, бот только показывает)

- Telegram ID берётся только из проверенного входящего update. Данные о родителе, ребёнке и занятии из `callback_data` не доверяются: ребёнок и занятие проверяются на сервере.
- Запись идёт через существующий `booking_signup` (или `waitlist_join` для очереди). Правила допуска, активности ребёнка, сроков, дублей и вместимости в новом коде не дублируются.
- Ребёнок должен быть связан с родителем, согласие не отозвано, ребёнок активен.
- Чужой или непривязанный Telegram-аккаунт не получает данных о чужих детях и не может записать ребёнка.
- Повторный update или повторное нажатие не создаёт вторую запись: ответ «Уже записаны».
- Одно место на двоих: при одновременной записи на последнее место получает один, второй видит «мест нет».
- Сообщения не рассылаются самовольно: ответ на нажатие — callback-ответ и правка кнопок того же сообщения. Уведомления о записи идут через уже существующую логику и выключатель `booking.notify` (по умолчанию выключен).
- Занятие в прошлом, отменённое или не найденное: отказ с понятным текстом.
- Изоляция семей и клубов: ребёнок другого клуба или другой семьи не появляется в списке и не принимается.

## Тексты результата

| Ситуация | Код | Текст |
|---|---|---|
| Записан | `ok` | Запись подтверждена: <имя> — <занятие> |
| Уже записан | `already` | Уже записаны: <имя> — <занятие> |
| Мест нет | `full` | Мест нет. Встать в очередь? (отдельная кнопка) |
| Места есть, а ребёнок просится в очередь | `free` | Есть свободные места: запишитесь на занятие, очередь не нужна. |
| Занятие началось или отменено | `closed` | Занятие уже началось или отменено. |
| Ребёнок не подходит (неактивен, не допущен) | `not_allowed` | Запись на это занятие для ребёнка недоступна. Подробности в приложении. |
| Нет привязки или согласие отозвано | `forbidden` | Нет доступа: вы не привязаны к этому ребёнку. |
| Аккаунт Telegram не найден | `unknown_user` | Не нашли ваш аккаунт. Откройте приложение и войдите. |
| Занятие не найдено | `not_found` | Этого занятия уже нет. |
| Прочая ошибка | `error` | Не получилось записать. Попробуйте позже или откройте приложение. |

## Тесты, которые должны быть зелёными

Логика бота (node, `tests/edge/booking-logic.test.mjs`):
- разбор `callback_data` (`bk`, `bs:<занятие>`, `bc:<занятие>:<ребёнок>`, `bw:<занятие>:<ребёнок>`); чужой или испорченный формат отклоняется;
- длина `callback_data` не больше 64 байт при любых UUID;
- меню занятий: один и несколько детей, занятие без мест, пустой список;
- ответ на каждый код результата; кнопки убираются только при успехе и при «уже записан».

База (pgTAP, `db/tests/rls_booking_telegram_test.sql`):
- один ребёнок, несколько детей, выбор нужного по префиксу;
- неизвестный Telegram ID, чужой ребёнок, непривязанный ребёнок, отозванное согласие, неактивный ребёнок;
- занятие прошедшее, отменённое, несуществующее, заполненное;
- повторный вызов (дубль) → `already`, одна запись в таблице;
- очередь: постановка только при полном занятии, чужой ребёнок отклоняется;
- конкурентная запись на последнее место (`db/tests/concurrency_booking.sh`: сценарий через `booking_signup_by_telegram`);
- HTTP-тест настоящего `index.ts` с заглушками (`tests/deno/tg-bot-booking.test.ts`): Telegram ID берётся из `from`, групповой чат и чужой `chat.id` отклоняются, сбой базы не ломает webhook;
- список занятий не показывает чужих детей и занятия другого клуба.

Регресс: все существующие тесты `tests/edge`, `tests/deno` и `db/tests` остаются зелёными, включая подтверждение матчей (RSVP) и кнопку «Занять место».

- Применение миграции 0158, деплой `tg-bot` и `tg-notify`, включение `booking.notify`, реальные сообщения и записи: делает только владелец.
