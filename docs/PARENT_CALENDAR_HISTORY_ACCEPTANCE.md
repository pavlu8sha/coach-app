# Календарь родителя: история после смены группы и жизненный цикл матчей (#628, #629, миграция 0194)

Условия приёмки. Тесты пишутся от них: `db/tests/rls_parent_calendar_history_test.sql`. Существующие проверки `rls_parent_calendar_test.sql`, `int_parent_family_access_test.sql` проходят без изменений.

## Проблема
Обе ошибки в одной функции `parent_calendar(p_player, p_from, p_to)` (актуальное тело — миграция 0178).
- #628 (INT-01). Групповые занятия, журнал тренировок и расписание берутся по **текущей** группе ребёнка. После перевода посещённые занятия старой группы пропадают, а занятия новой группы за прошлое показываются без отметок.
- #629 (INT-02). Матчи выбираются без учёта `matches.lifecycle_status`: черновики и отменённые матчи попадают в календарь, в том числе как «предстоящие».

## Условия приёмки
### #628
1. Групповое занятие входит в календарь, если на день занятия ребёнок состоял в группе занятия по `player_group_history` (`points_group_at`) **или** у ребёнка есть отметка `attendance` на этом занятии (отметка показывается независимо от группы).
2. День перевода относится к новой группе (`valid_to` не включается, правило 0120). Занятие старой группы в день перевода без отметки не показывается; с отметкой показывается.
3. Занятия новой группы до перевода без отметки ребёнка не показываются; после перевода показываются, отметка (если есть) возвращается.
4. Статус отметки берётся только у запрошенного ребёнка. Отметки других детей, в том числе одной группы, и занятия групп, в которых он не был и не отмечен, не попадают.
5. Запись журнала тренировок (`training_log`) определяется по названию группы ребёнка на дату записи, а не по текущей.
6. Будущее расписание (`weekly_schedule`) остаётся по текущей группе.
7. Для ребёнка без перевода результат не меняется.

### #629
8. Матчи `draft` и `cancelled` не возвращаются (ни как предстоящие, ни как прошедшие).
9. Будущий матч `published` возвращается со статусом `upcoming`; матчи `legacy` (старые, без жизненного цикла) возвращаются как прежде.
10. Фильтр действует и для матча, где у ребёнка есть строка состава.

### Доступ (не меняется)
11. Проверка опекуна с `parent_access_ok`, `42501 forbidden` для чужого ребёнка и после отзыва согласия, `not authenticated` без входа, ограничение диапазона дат.
12. Права на функцию: `execute` у `authenticated`, нет у `anon` и `public`; проверяется на базе с привилегиями по умолчанию Supabase. Новых функций и таблиц нет.

## Не входит
Матчи команды старой группы без участия ребёнка (по названию команды) остаются по текущей группе. Не меняем RLS, веб, `player_training_history`, другие RPC. Миграцию в проде применяет только Павел после `db/ops/preflight.sql`. Откат: `db/ops/rollback-0194-parent-calendar-history.sql` возвращает тело из 0178.
