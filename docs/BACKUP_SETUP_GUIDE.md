# Резервные копии боевой базы: пошаговая инструкция для владельца (Windows)

Это инструкция по настройке «с нуля», по одному действию на шаг, для компьютера на Windows 10/11. Техническое описание скриптов, хранения и восстановления: [`db/ops/BACKUP.md`](../db/ops/BACKUP.md). Условия приёмки: [`db/ops/BACKUP_ACCEPTANCE.md`](../db/ops/BACKUP_ACCEPTANCE.md).

Статус на 2026-11-13: скрипты в master (PR #621), боевая копия ещё не делалась. Настройка занимает около 40 минут один раз.

## Как это работает на Windows

Скрипты написаны для Linux-оболочки (bash). На Windows их запускают внутри **WSL**: это встроенная в Windows Ubuntu, которая ставится одной командой. Всё остальное (программы, ключ, копии) живёт внутри WSL. Это обычный способ, отдельных платных программ не нужно.

Каждый вечер компьютер сам забирает копию боевой базы Supabase, шифрует её и кладёт в папку `~/kickstart-backups` (внутри WSL). Старые копии удаляются сами: ежедневные через 14 дней, воскресные через 8 недель. Перед каждой миграцией копия делается вручную одной командой.

На бесплатном тарифе Supabase нет только автоматических копий в панели. `pg_dump` подключается к базе по обычной строке подключения, платные функции не нужны.

**Понадобится:**
- Компьютер на Windows, который вечером включён (копия делается в 21:30; если он был выключен, копия сделается при следующем включении).
- Пароль базы Supabase (если не помните, его можно сбросить, шаг 4).
- Доступ к репозиторию `coach-app` на GitHub.

**Важно:** копия содержит данные детей и платежи. Поэтому она всегда шифруется, а ключ от шифра хранится в двух местах. Пароль базы и ключ никому не присылайте, в чат и в GitHub не кладите.

Два вида окон ниже:
- **PowerShell** (обычная программа Windows): Пуск → «PowerShell». Для шага 0 откройте его «от имени администратора».
- **Ubuntu** (окно WSL): Пуск → «Ubuntu». Это основное окно, в нём идут все остальные шаги.

Команды вставляются правой кнопкой мыши, потом Enter.

## Шаг 0. Установить WSL (один раз, PowerShell от администратора)

```
wsl --install -d Ubuntu
```

После установки перезагрузите компьютер. При первом запуске Ubuntu попросит придумать имя пользователя и пароль (это пароль только для Ubuntu, не от Supabase, запомните его). Если WSL уже стоит, шаг пропустить.

## Шаг 1. Установить программы (окно Ubuntu)

```
sudo apt update
sudo apt install -y postgresql-common age git curl
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh -y
sudo apt install -y postgresql-17 postgresql-client-17
pg_dump --version
```

Последняя команда должна показать `pg_dump (PostgreSQL) 17.…`. Версия `pg_dump` не может быть старше версии базы на Supabase (она видна в Project Settings → Database). Если у Supabase версия выше 17, замените `17` на нужную в обеих командах.

Для работы с GitHub:

```
sudo apt install -y gh
```

Если `gh` не нашёлся, установите по инструкции на cli.github.com (раздел Linux).

## Шаг 2. Скачать скрипты

Скачивать нужно **внутри Ubuntu** (в домашнюю папку `~`), а не в папки Windows (`/mnt/c/...`): иначе Windows испортит переводы строк, и скрипты не запустятся.

```
gh auth login
gh repo clone pavlu8sha/coach-app ~/coach-app
cd ~/coach-app && git pull
```

На первой команде выберите GitHub.com → HTTPS → вход через браузер (покажет код, вводите его на странице github.com/login/device). Скрипты уже в `master`, переключать ветку не нужно.

## Шаг 3. Создать ключ шифрования

```
mkdir -p ~/.config/kickstart
age-keygen -o ~/.config/kickstart/age-key.txt
```

Команда покажет строку `Public key: age1…`. Это открытая часть ключа, скопируйте её для шага 5.

**Сразу сохраните файл ключа во втором месте.** Команды:

```
cd ~/.config/kickstart
explorer.exe .
```

откроют эту папку в Проводнике Windows. Файл `age-key.txt` положите в менеджер паролей или на флешку, которая хранится отдельно от компьютера. Если компьютер сломается и ключ пропадёт, все копии станут бесполезны. В ту же облачную папку, где лежат копии, ключ не кладите.

## Шаг 4. Взять строку подключения в Supabase

1. Supabase → ваш проект → кнопка **Connect** вверху.
2. Выбрать **Session pooler** (не Direct connection: на бесплатном тарифе оно работает только по IPv6, а у многих сетей IPv6 нет).
3. Скопировать строку вида `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres` и заменить `[YOUR-PASSWORD]` на пароль базы (без квадратных скобок).

Если пароль не помните: Project Settings → Database → Reset database password → Generate. Сгенерированный пароль из букв и цифр лучше всего: символы `@ # / ' :` ломают строку. Приложение и бот работают через ключи API, а не через этот пароль, в коде репозитория он не используется.

## Шаг 5. Записать настройки в файл

```
nano ~/.config/kickstart/backup.env
```

В открывшемся окне вставить две строки со своими значениями:

```
SUPABASE_DB_URL='строка из шага 4'
AGE_RECIPIENT='age1… из шага 3'
```

Сохранить: Ctrl+O, Enter, выйти: Ctrl+X. Закрыть файл от других пользователей:

```
chmod 600 ~/.config/kickstart/backup.env
```

## Шаг 6. Первая копия

```
cd ~/coach-app && db/ops/backup-pg-dump.sh
```

Успех: последние строки `OK: /home/<имя>/kickstart-backups/daily/kickstart-….dump.age`. Копия занимает от нескольких секунд до минуты.

| Если написано | Что сделать |
|---|---|
| «нет подключения к БД» | Проверить пароль и что взята строка Session pooler |
| «pg_dump 15 старше сервера» | Поставить клиент нужной версии (шаг 1) |
| «должен иметь права 600» | Выполнить `chmod 600` из шага 5 |
| «bad interpreter» или странные символы `^M` | Скрипты скачаны не в WSL или Windows испортил переводы строк: повторить шаг 2 в папке `~` |
| что-то другое | Прислать текст ошибки (пароля в нём нет) |

## Проверить, что копия восстанавливается

Копия, которую ни разу не восстанавливали, не считается копией. Проверка идёт целиком у вас в WSL, боевую базу она не трогает. Сделать после первой копии, дальше раз в месяц.

Один раз задайте пароль локальной базе (это тестовый пароль для базы внутри WSL, он ни с чем не связан):

```
sudo service postgresql start
sudo -u postgres psql -c "alter user postgres password 'local-test'"
```

Дальше сама проверка:

```
cd ~/coach-app
PGPASSWORD=local-test TEST_PG_URL=postgresql://postgres@localhost:5432 AGE_IDENTITY=~/.config/kickstart/age-key.txt db/ops/backup-restore-check.sh "$(ls -t ~/kickstart-backups/daily/*.dump.age | head -1)"
```

Успех: последняя строка `ПРОЙДЕНО`. Если первый раз будет `НЕ ПРОЙДЕНО`, это не значит, что копия плохая: пришлите строки ошибок, проверку можно донастроить под Supabase. Скрипт создаёт свою временную базу и удаляет только её, существующие базы не трогает.

Результат первой проверки впишите в журнал в `db/ops/BACKUP.md` (раздел 8).

## Включить ежедневную копию

Автозапуск делает «Планировщик заданий» Windows. Откройте **PowerShell** (обычный, не от администратора) и вставьте целиком:

```
$a = New-ScheduledTaskAction -Execute "wsl.exe" -Argument "-e bash -lc 'mkdir -p ~/kickstart-backups; cd ~/coach-app && git pull -q; db/ops/backup-pg-dump.sh >> ~/kickstart-backups/backup.log 2>&1'"
$t = New-ScheduledTaskTrigger -Daily -At 9:30PM
$s = New-ScheduledTaskSettingsSet -StartWhenAvailable
Register-ScheduledTask -TaskName "KickstartBackup" -Action $a -Trigger $t -Settings $s
```

Параметр `-StartWhenAvailable` значит: если в 21:30 компьютер был выключен, копия сделается при следующем включении. Если WSL работает от другого дистрибутива, добавьте в `-Argument` перед `-e` текст `-d Ubuntu`.

Проверить, что задание создалось: Пуск → «Планировщик заданий» → Библиотека планировщика → KickstartBackup. Правой кнопкой → «Выполнить» запустит его сразу; через минуту проверьте журнал (команда ниже).

**Раз в неделю** посмотреть, что копии идут (окно Ubuntu):

```
ls -lt ~/kickstart-backups/daily | head -5
tail -3 ~/kickstart-backups/backup.log
```

Верхний файл должен быть за вчера или сегодня, в журнале строка `OK:`.

## Вторая точка хранения

Если копии лежат только на этом компьютере, то с ним они и пропадут. Раз в неделю копируйте папку `weekly` на внешний диск или в облачную папку Windows (OneDrive, Google Диск). Например, на диск `D:`:

```
mkdir -p /mnt/d/kickstart-backups-copy
cp -r ~/kickstart-backups/weekly /mnt/d/kickstart-backups-copy/
```

Файлы зашифрованы, в облако их класть можно. Ключ `age-key.txt` туда же не кладите.

## Перед каждой миграцией

1. Сделать отдельную копию (она не удаляется автоматически): `cd ~/coach-app && BACKUP_KIND=premigration db/ops/backup-pg-dump.sh`
2. Убедиться, что в конце написано `OK:`.
3. Как обычно: `db/ops/preflight.sql` в SQL Editor, потом миграция.

## Если данные пропали или испортились

**Не восстанавливайте копию поверх боевой базы сами.** Тренеры и родители работают каждый день, и полный откат сотрёт всё, что внесено после копии. Напишите разработчику: восстанавливаем точечно, только нужные строки, сначала на локальной копии. Подробности: `db/ops/BACKUP.md`, раздел 6.

Файлы из Storage (PDF документов сборов) в копию не входят. Если они важны, иногда скачивайте их из Supabase → Storage.

## Решение, которое остаётся за владельцем

Платный тариф Supabase: Pro (ежедневные копии, около $25 в месяц) и PITR (восстановление на момент времени, около $100 в месяц, по `docs/LAUNCH_AUDIT.md`). Он не заменяет внешней копии, но снимает зависимость от включённого компьютера. Рекомендация: начать со скриптов сразу, решение о Pro принять до 1 декабря.

## Что проверено, а что нет

Скрипты проверены на Linux (тот же Ubuntu, что внутри WSL): дамп, шифрование, восстановление, ротация. На самом Windows, в WSL и через Планировщик заданий эти шаги ещё не выполнялись, поэтому при первом прогоне возможны мелкие поправки. Если что-то не сработает, пришлите текст ошибки.
