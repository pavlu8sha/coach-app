# Резервные копии боевой базы: пошаговая инструкция для владельца (Mac)

Это инструкция по настройке «с нуля», по одному действию на шаг. Техническое описание скриптов, хранения и восстановления: [`db/ops/BACKUP.md`](../db/ops/BACKUP.md). Условия приёмки: [`db/ops/BACKUP_ACCEPTANCE.md`](../db/ops/BACKUP_ACCEPTANCE.md).

Статус на 2026-11-13: скрипты в master (PR #621), боевая копия ещё не делалась. Настройка занимает около 30 минут один раз.

## Что получится

Каждый вечер Mac сам забирает копию боевой базы Supabase, шифрует её и кладёт в папку `~/kickstart-backups`. Старые копии удаляются сами: ежедневные через 14 дней, воскресные через 8 недель. Перед каждой миграцией копия делается вручную одной командой.

На бесплатном тарифе Supabase нет только автоматических копий в панели. `pg_dump` подключается к базе по обычной строке подключения, платные функции не нужны.

**Понадобится:**
- Mac, который вечером включён (копия делается в 21:30).
- Пароль базы Supabase (если не помните, его можно сбросить, шаг 4).
- Доступ к репозиторию `coach-app` на GitHub.

**Важно:** копия содержит данные детей и платежи. Поэтому она всегда шифруется, а ключ от шифра хранится в двух местах. Пароль базы и ключ никому не присылайте, в чат и в GitHub не кладите.

Все команды вставляются в программу «Терминал» (Cmd+Пробел, «Терминал»). После вставки нажать Enter.

## Шаг 1. Установить программы

Если Homebrew ещё нет (команда `brew --version` пишет «command not found»), сначала установите его по команде с сайта brew.sh. Потом:

```
brew install postgresql@17 age gh
echo 'export PATH="/opt/homebrew/opt/postgresql@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
pg_dump --version
```

Последняя команда должна показать `pg_dump (PostgreSQL) 17.…`. Версия `pg_dump` не может быть старше версии базы на Supabase (она видна в Project Settings → Database). Если у Supabase версия выше 17, установите соответствующую `postgresql@<версия>` и поправьте путь в PATH. На старом Mac с процессором Intel вместо `/opt/homebrew` везде писать `/usr/local`.

## Шаг 2. Скачать скрипты

```
gh auth login
gh repo clone pavlu8sha/coach-app ~/coach-app
cd ~/coach-app && git pull
```

На первой команде выберите GitHub.com → HTTPS → вход через браузер. Скрипты уже в `master`, переключать ветку не нужно.

## Шаг 3. Создать ключ шифрования

```
mkdir -p ~/.config/kickstart
age-keygen -o ~/.config/kickstart/age-key.txt
```

Команда покажет строку `Public key: age1…`. Это открытая часть ключа, скопируйте её для шага 5.

**Сразу сохраните файл ключа во втором месте.** Команда `open ~/.config/kickstart` откроет папку. Файл `age-key.txt` положите в менеджер паролей или на флешку, которая хранится отдельно от Mac. Если Mac сломается и ключ пропадёт, все копии станут бесполезны. В ту же облачную папку, где лежат копии, ключ не кладите.

## Шаг 4. Взять строку подключения в Supabase

1. Supabase → ваш проект → кнопка **Connect** вверху.
2. Выбрать **Session pooler** (не Direct connection: на бесплатном тарифе оно работает только по IPv6, а у многих сетей IPv6 нет).
3. Скопировать строку вида `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres` и заменить `[YOUR-PASSWORD]` на пароль базы (без квадратных скобок).

Если пароль не помните: Project Settings → Database → Reset database password → Generate. Сгенерированный пароль из букв и цифр лучше всего: символы `@ # / ' :` ломают строку. Приложение и бот работают через ключи API, а не через этот пароль, в коде репозитория он не используется.

## Шаг 5. Записать настройки в файл

```
nano ~/.config/kickstart/backup.env
```

В открывшемся окне вставить две строки со своими значениями:

```
SUPABASE_DB_URL='строка из шага 4'
AGE_RECIPIENT='age1… из шага 3'
```

Сохранить: Ctrl+O, Enter, выйти: Ctrl+X. Закрыть файл от других пользователей Mac:

```
chmod 600 ~/.config/kickstart/backup.env
```

## Шаг 6. Первая копия

```
cd ~/coach-app && db/ops/backup-pg-dump.sh
```

Успех: последние строки `OK: /Users/…/kickstart-backups/daily/kickstart-….dump.age`. Копия занимает от нескольких секунд до минуты.

| Если написано | Что сделать |
|---|---|
| «нет подключения к БД» | Проверить пароль и что взята строка Session pooler |
| «pg_dump 15 старше сервера» | Не сработала строка PATH из шага 1: закрыть и снова открыть Терминал |
| «должен иметь права 600» | Выполнить `chmod 600` из шага 5 |
| что-то другое | Прислать текст ошибки (пароля в нём нет) |

## Проверить, что копия восстанавливается

Копия, которую ни разу не восстанавливали, не считается копией. Проверка идёт целиком на вашем Mac, боевую базу она не трогает. Сделать после первой копии, дальше раз в месяц.

```
brew services start postgresql@17
cd ~/coach-app
TEST_PG_URL="postgresql://$USER@localhost:5432" AGE_IDENTITY=~/.config/kickstart/age-key.txt db/ops/backup-restore-check.sh "$(ls -t ~/kickstart-backups/daily/*.dump.age | head -1)"
brew services stop postgresql@17
```

Успех: последняя строка `ПРОЙДЕНО`. Если первый раз будет `НЕ ПРОЙДЕНО`, это не значит, что копия плохая: пришлите строки ошибок, проверку можно донастроить под Supabase. Скрипт создаёт свою временную базу и удаляет только её, существующие базы не трогает.

Результат первой проверки впишите в журнал в `db/ops/BACKUP.md` (раздел 8).

## Включить ежедневную копию

Одна команда добавляет запуск каждый день в 21:30:

```
(crontab -l 2>/dev/null; echo '30 21 * * * cd $HOME/coach-app && PATH=/opt/homebrew/opt/postgresql@17/bin:/opt/homebrew/bin:/usr/bin:/bin db/ops/backup-pg-dump.sh >> $HOME/kickstart-backups/backup.log 2>&1') | crontab -
```

Проверить, что добавилось: `crontab -l`. Если в 21:30 Mac спит или выключен, копия в этот день не делается. Время можно поменять: `30 21` это минуты и часы.

**Раз в неделю** посмотреть, что копии идут:

```
ls -lt ~/kickstart-backups/daily | head -5
tail -3 ~/kickstart-backups/backup.log
```

Верхний файл должен быть за вчера или сегодня, в журнале строка `OK:`.

## Вторая точка хранения

Если копии лежат только на Mac, то с ним они и пропадут. Раз в неделю копируйте папку `~/kickstart-backups/weekly` на внешний диск или в iCloud / Google Диск. Файлы зашифрованы, в облако их класть можно. Ключ `age-key.txt` туда же не кладите.

## Перед каждой миграцией

1. Сделать отдельную копию (она не удаляется автоматически): `cd ~/coach-app && BACKUP_KIND=premigration db/ops/backup-pg-dump.sh`
2. Убедиться, что в конце написано `OK:`.
3. Как обычно: `db/ops/preflight.sql` в SQL Editor, потом миграция.

## Если данные пропали или испортились

**Не восстанавливайте копию поверх боевой базы сами.** Тренеры и родители работают каждый день, и полный откат сотрёт всё, что внесено после копии. Напишите разработчику: восстанавливаем точечно, только нужные строки, сначала на локальной копии. Подробности: `db/ops/BACKUP.md`, раздел 6.

Файлы из Storage (PDF документов сборов) в копию не входят. Если они важны, иногда скачивайте их из Supabase → Storage.

## Решение, которое остаётся за владельцем

Платный тариф Supabase: Pro (ежедневные копии, около $25 в месяц) и PITR (восстановление на момент времени, около $100 в месяц, по `docs/LAUNCH_AUDIT.md`). Он не заменяет внешней копии, но снимает зависимость от включённого Mac. Рекомендация: начать со скриптов сразу, решение о Pro принять до 1 декабря.
