# Условия приёмки: потолок опекунов и проверка клуба при подтверждении привязки (миграция 0199)

Решение владельца 2026-11-16: не больше 4 опекунов с доступом (parent_access_ok) на одного ребёнка.

1. `decide_link(r, true)` отклоняется ошибкой `guardian limit reached` (код 54000), если у ребёнка уже 4 активных опекуна
   (по parent_access_ok), не считая самого подающего родителя. Запрос остаётся «ждёт» (статус не меняется, связь не создаётся).
2. При 3 активных опекунах четвёртый подтверждается.
3. Опекуны без доступа (parent_access_ok = false, например отозванная связь) в потолок не входят.
4. `decide_link(r, true)` отклоняется ошибкой `club mismatch` (код 42501), если у родителя `users.club_id` задан и не равен `players.club_id`.
   Если `users.club_id` пуст (родитель ещё не привязан), проверка пропускается: клуб один, как в поиске (0089).
5. Отклонение запроса (`approve = false`) потолком и клубом не ограничивается.
6. Прежнее поведение 0162 не меняется: только админ, повторное решение запрещено, сброс согласий при создании связи.
7. Права: `decide_link` выполняют только вошедшие (authenticated), не anon, на базе с привилегиями Supabase по умолчанию.
8. Админ в карточке запроса видит, кто уже привязан к ребёнку и сколько детей у родителя (веб, `AdminLinkHints.test.tsx`).
