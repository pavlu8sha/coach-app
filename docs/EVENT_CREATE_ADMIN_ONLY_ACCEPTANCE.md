# Создавать события может только администратор (миграция 0195)

Условия приёмки. Тесты пишутся от них: `db/tests/rls_events_test.sql`, `db/tests/rls_event_status_test.sql`, `web/src/screens/CoachMatches.test.tsx`.

## Проблема
Тренер случайно создал событие-чемпионат «FC Tbilisi-2025» (U9) вместо товарищеского матча: кнопка «Новое событие» и функция `event_create` (0051) доступны любому тренеру.
Решение владельца (2026-11-13): тренерам разрешены только товарищеские матчи; чемпионаты, фестивали, кубки создаёт только администратор.

## Условия приёмки
1. `event_create` вызывает только администратор. Тренер, родитель, игрок: `42501` (`forbidden`), неавторизованный: `42501` (`not authenticated`). Событие при отказе не создаётся.
2. Администратор создаёт событие как раньше: взнос, копирование состава, типы championship/festival/cup не меняются.
3. Тренер по-прежнему: видит список событий, ведёт состав существующего события, добавляет игру существующего события, сохраняет товарищеские матчи (`save_match`). `event_list`, `event_roster*`, `event_add_game`, `save_match` не меняются.
4. Таблицы `tournaments`, `tournament_fees` по-прежнему закрыты от тренера (RLS не менялся, прямых прав не открываем); проверка `insert into tournaments` от тренера даёт отказ.
5. Права на функцию: `execute` у `authenticated`, нет у `anon` и `public`; проверка на базе с привилегиями по умолчанию Supabase.
6. Экран: тренеру кнопка «Новое событие» не показывается, в подсказке «Добавить матч» нет предложения создать событие; администратору всё прежнее. Прямой вызов `event_create` тренером даёт понятную ошибку.
7. Продуктовое правило соблюдено: тексты без акцента на голах и сравнений детей.

## Не входит
Не удаляем уже созданное: чемпионат «FC Tbilisi-2025» удаляется отдельным скриптом `db/ops/delete-event-fc-tbilisi-2025.sql` (применяет только Павел, после проверок скрипта). Не меняем RLS, `save_match`, `save_match_team`. Не применяем миграцию в проде.
