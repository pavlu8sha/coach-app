# Передача проекта: состояние на 23.10.2026 (Supabase и приложение для родителей)

Это актуальная сводка для того, кто продолжает работу (Claude Code или человек). Старый `CLAUDE_HANDOFF.md` описывает состояние от 21.10 и Apps Script-часть; про Supabase и приложение для родителей читайте этот файл. Перед работой проверьте `git log`, открытые PR и CI: документ — снимок.

## 1. Что строим

Павел (владелец, футбольный тренер, не разработчик) ведёт клуб FC KickStart Tbilisi. Данные клуба жили в Google Таблицах и Apps Script («coach-app», корень репозитория: `*.js`, `*.html`, `appsscript.json`, выгрузка через `clasp push`). Цель: перенести данные в Supabase и сделать для родителей приложение: Telegram Mini App и обычный сайт (PWA). Качество важнее скорости.

Что уже работает end-to-end: вход через Telegram → сессия Supabase → RLS → экраны родителя и администратора.

## 2. Правила работы с владельцем (соблюдать строго)

- **Google Таблицы только читать**, никогда не менять и не удалять (ему передают копии, но правило общее).
- **Запись в базу только после его «да»**; миграции он сам применяет в Supabase SQL Editor (вставляете ему текст целиком, он нажимает Run; предупреждение «destructive operations» при `drop`/`delete`/`update` ожидаемо).
- **Слияние PR только после слова «сливай»**; после слияния дожидаться CI, если появились новые коммиты.
- **Секреты в чат не присылать** и самим не просить (ключ `sb_secret_…` вводится им через `Read-Host`; токен бота лежит в секретах функции).
- Он работает в **Windows**, команды давать в синтаксисе PowerShell/cmd: `npx.cmd`, а не `npx`; `$env:ИМЯ` только в PowerShell; `npm install -g supabase` не поддерживается.
- Объяснять простым языком, без лишней терминологии; называть конкретные следующие шаги. Если он не пишет про результат проверки, значит всё в порядке.
- Телеграм есть почти у всех родителей. Языки интерфейса: русский, для согласия русский и английский.

## 3. Архитектура

| Часть | Где | Заметки |
|---|---|---|
| Старое приложение | корень репозитория, Apps Script | `clasp push`; `.claspignore` исключает `supabase/`, `web/`, `scripts/`, `tests/`, `db/`, `docs/` |
| База | Supabase, проект **Kickstart**, ref `ypxbwhjsqkrciozdhajf` | Postgres + RLS; миграции `db/migrations/` |
| Вход | Edge Function `supabase/functions/tg-auth` | проверка подписи `initData`, создание пользователя Auth, возврат `token_hash`; ограничение частоты (миграция 0016) |
| Приложение | `web/` (Vite, React 19, TypeScript), Cloudflare Pages: https://coach-app-84b.pages.dev/ | кнопка меню в BotFather ведёт на этот адрес; сборка = `tsc --noEmit && vite build` |
| Импорт данных | `scripts/import/*.mjs` | без зависимостей, по умолчанию «сухой прогон», запись с `--write` |

Вход подробно: проект использует асимметричные ключи подписи JWT, поэтому **свои JWT не выпускаем**. Функция создаёт пользователя Auth (`tg<id>@telegram.invalid`) и отдаёт одноразовый `token_hash`; клиент обменивает его через `supabase.auth.verifyOtp({ token_hash, type: 'email' })`. `users.id` обязан совпадать с id пользователя Auth: на это опираются RLS-функции (`current_user_id()` читает `sub`). Провайдер Email в Supabase должен быть включён.

## 4. База данных

Миграции применены в боевой Supabase: **0001–0009, 0011–0016** (0010 нет: лагеря и настройки — задача OpenCode, в репозитории пока не появилась). Ключевые:

- 0001/0002: схема и RLS; функции `is_admin()`, `current_user_id()`, `is_guardian_of()`, `is_coach_of_player()`, `is_coach_of_group()`, `group_rating()`.
- 0003/0004: «наследные» домены (оплаты, экипировка, расписание, лагеря и т.п.) и их RLS.
- 0011/0012: импорт посещаемости и правила рейтинга.
- 0013: родитель читает группу своего ребёнка (`is_guardian_in_group`).
- 0014: запросы родителя на связь с ребёнком (`link_requests`, функции `search_players_for_link`, `request_link`, `decide_link`).
- 0015: согласие (`consent_versions`, версия и время в запросе и в `player_guardians`).
- 0016: `rate_limits` и `rate_limit_hit` (только `service_role`).

Права в Supabase не выдаются автоматически: новые таблицы и функции требуют явных `grant`/`revoke` (см. образцы в 0002, 0014, 0016).

Импортировано из таблиц (из Google): реестр (203 игрока, 4 активных без даты рождения из 23 без даты), оплаты, экипировка, события/матчи/взносы, цели, индивидуальные тренировки, расписание и журнал тренировок, посещаемость (авг–окт 2026: 367 тренировок, 5128 отметок), даты рождения (203 из 203 с датой в таблицах), правила рейтинга (6 правил) и история баллов (4213 начислений).

## 5. Тесты и CI

- `node --test tests/*.mjs tests/import/*.test.mjs tests/edge/*.test.mjs`: unit-тесты (около 250).
- `scripts/run-db-tests.sh`: поднимает чистую БД, применяет все миграции, гоняет `db/tests/rls*_test.sql` (pgTAP, 39 проверок). Нужны PostgreSQL 16 и pgTAP. Файлы тестов доступа называть `rls*_test.sql`, чтобы раннер их подхватил.
- GitHub Actions (`.github/workflows/test.yml`): `test`, `db`, `web`. Плюс Cloudflare Pages собирает ветку. Прежде чем просить слияние, дождаться всех четырёх.
- Локально в песочнице `npm install` может не работать (нет доступа к реестру), поэтому типы проверяет CI; логи GitHub Actions из песочницы недоступны, ошибку приходится искать по коду.

## 6. Экраны приложения (на момент записи)

Родитель: «Ребёнок» (имя, группа, сумма баллов, последние начисления; блок «Добавить ребёнка» с поиском по имени от 3 букв и согласием ru/en), «Расписание» (тренировки группы, ближайшие матчи, три последних результата), «Оплата» (внесённые суммы по месяцам).
Администратор: «Запросы» (подтвердить/отклонить связь), «Дети» (все активные игроки по группам с баллами), «Расписание» (все группы), «Ребёнок» только если у него есть свои дети.

Два аккаунта в базе: личный Павла (обычный пользователь, к нему привязан тестовый ребёнок) и аккаунт клуба «FC KickStart Tbilisi Admin» (`is_admin = true`). Права администратора выдаются вручную SQL: `update users set is_admin = true where telegram_id = …`.

## 7. Известные ограничения и долги

1. **Согласие родителя — черновик**, юридическую проверку не проходил (`docs/CONSENT.md`, версия `draft-2026-10`, текст в `web/src/lib/consent.ts`). Родителям приложение не открывать до проверки.
2. **Отзыв согласия** только вручную (`consent_revoked_at` в `player_guardians`); в интерфейсе кнопки нет. Экспорт и удаление данных по запросу не сделаны.
3. **Оплата**: в импортированных данных только внесённые суммы по месяцам (даты платежей = 1-е число). Сумм «к оплате» и цен нет, поэтому долг не показываем. Нужен импорт `prices` и решение про скидки и пропущенные месяцы.
4. **Широкое чтение**: политики `matches_read`, `weekly_schedule_read`, `rules_read` разрешают любому вошедшему пользователю. Нужно сузить (группы ребёнка/тренера/администратор).
5. **Тестовые связи**: у связей, созданных руками, `consent_version` = `test-2026-10` или `link-request-v0`, настоящего согласия там нет.
6. **Уведомления в Telegram** (администратору о новом запросе, родителю о решении) не сделаны: идея в `docs/LAUNCH_AUDIT.md`.
7. **Вход только из Telegram**; в обычном браузере приложение просит открыть из Telegram.
8. Павел отметил на 23.10, что в админских экранах есть «несостыковки и неточности»; список он пришлёт позже.
9. `matches.team` сопоставляется с названием группы по тексту (например `U10-A`); если у какой-то группы матчей нет, проверить соответствие названий.

## 9. Практические заметки

- PR открываются через REST (`gh api repos/pavlu8sha/coach-app/pulls …`): GraphQL из сессии Claude недоступен. Слияние: `PUT /pulls/<n>/merge` с `merge_method=squash`.
- Хук Stop жалуется «no remote branch», когда ветка не привязана к удалённой: помогает `git push -u origin <ветка>` (даже если «Everything up-to-date»).
- Каждая новая миграция: добавлять `grant`/`revoke` явно; писать pgTAP-тест в `db/tests/rls_*_test.sql`; прогонять `scripts/run-db-tests.sh`; прислать Павлу SQL для SQL Editor; после применения он проверяет в приложении.
- Деплой функции: `npx.cmd supabase@latest functions deploy tg-auth --project-ref ypxbwhjsqkrciozdhajf` (предупреждение «Docker is not running» безвредно). Секрет функции `TELEGRAM_BOT_TOKEN` уже задан.
- Импорты читают таблицы только на чтение; переменные окружения `SUPABASE_URL` (без `/rest/v1` и без слэша на конце), `SUPABASE_SERVICE_KEY` (секретный ключ), `CLUB_ID`.
- Сервер отдаёт не больше 1000 строк за запрос: большие выборки читать страницами (`order` + `range`).
- PostgREST: у таблицы с двумя внешними ссылками на одну таблицу встроенный запрос нужно уточнять (`users!link_requests_user_id_fkey(...)`).
