# Выбор роли при первом входе: сохранение и ошибки (#704, #705, миграция 0212)

Условия приёмки. Тесты пишутся от них: `db/tests/rls_user_role_test.sql` (SQL), `web/src/screens/RoleSelect.test.tsx`, `web/src/App.test.tsx` (раздел «выбор роли»).

## Проблема
Родитель выбирает «Родитель», но перехода не происходит (#704), а при ошибке показывается технический текст Supabase (#705).
Найдено в коде (подтверждено тестами до исправления):
- `set_my_role` (0022) делает `update users ... where id = current_user_id()`; если строки нет, update затрагивает 0 строк и функция успешно завершается. `NULL` как роль проходит мимо проверки `r not in (...)`.
- `RoleSelect.pick` не обёрнут в try/finally: при отклонённом Promise (сеть, обрыв в webview Telegram) `busy` остаётся выставленным, все кнопки заблокированы, текста ошибки нет. Для пользователя это «нажал и ничего не происходит».
- `RoleSelect` выводит `res.error.message` как есть; `becomeGuest` при ошибке молча выходит.
- Экран идёт дальше по ответу RPC, фактическое сохранение роли не перечитывается.
Точная причина у конкретного родителя по данным прода не проверялась (производственных запросов нет); исправляются все подтверждённые пути.

## Условия приёмки
### #704 — сохранение роли
1. `set_my_role('parent' | 'coach' | 'child' | 'guest')` от авторизованного пользователя с профилем меняет `chosen_role` его строки; повторный вызов меняет роль снова.
2. `set_my_role(NULL)` и недопустимое значение (`'admin'`, `''`, `'Parent'`) отклоняются: `22023`, строка не меняется.
3. Если строки `users` текущего пользователя нет, функция не сообщает об успехе: ошибка `P0002` (`profile_missing`), ничего не создаётся и ничьи строки не меняются. Профиль создаёт только вход (Edge Function), из SQL роль его не создаёт.
4. Без авторизации (`current_user_id() is null`): `42501`, как раньше.
5. Чужую строку функция не меняет; прямая запись в `users` по-прежнему закрыта; выбор роли не даёт `is_admin`.
6. Права на функцию не меняются: `execute` у `authenticated`, нет у `anon` и `public`; проверено на базе с привилегиями по умолчанию Supabase.
7. Экран переходит дальше только после подтверждённого сохранения: после RPC читается `users.chosen_role` текущего пользователя, и `onDone` вызывается, только если прочитанная роль равна выбранной. Иначе — ошибка и возможность повторить.
8. Роль после обновления страницы и повторного входа сохраняется (App читает `chosen_role` из базы): родитель с `chosen_role='parent'` без детей видит кабинет родителя, а не выбор роли.
9. Повторная попытка после ошибки сохраняет роль и ведёт дальше.

### #705 — ошибки
10. Ответ RPC с ошибкой и отклонённый Promise (сетевой сбой) дают короткое русское сообщение; в интерфейсе нет текста ошибки Supabase/SQL, имён RPC (`set_my_role`), `stack`, кодов вроде `42501`.
11. Тексты различают: нет сети или сбой сервиса («Не удалось сохранить роль. Проверьте соединение и попробуйте ещё раз»), сессия/профиль недоступны («Не удалось найти ваш профиль. Закройте приложение и откройте его заново»), прочее — общий текст. Технические детали пишутся только в `console.error`.
12. После любой ошибки `busy` сбрасывается, кнопки снова доступны, повторное нажатие работает. Во время запроса остальные кнопки заблокированы.
13. `becomeGuest` (App): при ошибке RPC и при отклонённом Promise пользователь видит понятное сообщение, роль в интерфейсе не меняется, повторить можно; при успехе переходит как раньше. Двойное нажатие во время запроса не отправляет второй запрос.
14. Гостевой режим и права не расширяются: роль остаётся подсказкой интерфейса.

## Не входит
Не меняем модель ролей, RLS, права, onboarding целиком. Миграцию в проде не применяем (применяет Павел после свежего `db/ops/preflight.sql`). Экраны `Link`, `LinkStatus`, `TrialForm` с тем же паттерном только фиксируются в отчёте.
