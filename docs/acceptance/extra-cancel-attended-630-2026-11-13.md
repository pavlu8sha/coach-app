# Условия приёмки: отмена дополнительной тренировки после отметки посещения (#630)

Решение владельца 13.11.2026 (комментарий в #630): вариант A. Диагностика: `/mnt/project-files/issue-630/diagnosis-630.md`.
Область: функция `extra_cancel_session` (миграция 0196, create or replace; таблицы, права, баллы, серии, финансовая семантика не меняются).

## Условия
1. Отмена запрещена, если у любой записи тренировки `attended = true`: ошибка `22023`, сообщение `attendance marked`. Побочных эффектов нет: сессия не отменена, записи, оплаты, баллы, журнал отмен, уведомления и журнал действий не менялись.
2. Администратор может снять отметку (`extra_set_attended(..., null)`) и повторить отмену. Баллы при снятии отметки сторнируются штатным механизмом с записью в `points_ledger_audit`.
3. `attended = false` отмену не блокирует. Такая запись переносится в `booking_cancellations` и удаляется из `extra_bookings`: оплаченная получает `awaiting` (сумма = `paid_amount`, иначе сумма тренировки), неоплаченная `cancelled`. Записи без отметки ведут себя как раньше.
4. Уведомление об отмене получают семьи всех записей, перенесённых в журнал (без отметки и с `attended = false`).
5. Повторная отмена: `55000 session cancelled`, без новых строк журнала, аудита, уведомлений.
6. Повторное снятие отметки и повторный `points_reconcile_extra` не создают повторного сторно.
7. Серия игрока не меняется (дополнительные тренировки в серию не входят).
8. Отменить может только администратор; тренер и родитель получают `forbidden`. Журнал отмен видит только администратор; чужая семья уведомлений не получает.
9. `points_consistency(false)` после цепочки: 0 изменений, 0 исключений; сумма `service_payments` не меняется.
10. Страж: после любой допустимой цепочки нет отменённой сессии с `attended = true`.
11. Гонка отметки и отмены не оставляет отменённую сессию с `attended = true`: функция блокирует записи сессии до проверки.
12. Интерфейс: текст подтверждения не обещает перенос в историю отмен отмеченных; про отказ `attendance marked` показывается понятное сообщение. `docs/TRAININGS_BOOKING.md` обновлён.
13. Историю не правим: `db/ops/readonly-extra-cancel-attended-630.sql` только считает аномалии (отменённые сессии с `attended = true` и оплаченные `attended = false` без строки журнала). Не запускается в проде без слова Павла; backfill вне #630.

## Вне #630
Операция «закрыть частично состоявшуюся тренировку» (отложено владельцем). Исправление существующих данных.

## Миграция и rollback
