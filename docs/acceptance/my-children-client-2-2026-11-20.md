# Условия приёмки: ещё три экрана родителя берут детей из `my_children()` (Home, Schedule, ParentCalendar)

Продолжение `docs/acceptance/my-children-client-2026-11-20.md` (К1-К6, #784). Миграция 0215 применена в проде (Павел, 2026-11-20). Серверных изменений нет.

Экраны: «Мой ребёнок» (Home), «Расписание» родителя (Schedule, не режим администратора), «Календарь» родителя (ParentCalendar).
ParentCamps не меняется: он не фильтрует по полю отзыва старой модели, а берёт `players(...)`, который режет RLS (`parent_access_ok`), и ему нужны `club_id` и `status`, которых в `my_children()` нет.

- **К7. Источник.** Три экрана получают детей вызовом `my_children()` (через `loadMyChildren`), таблицу `player_guardians` не читают, фильтра по полю отзыва старой модели в них нет. Ребёнок, которого вернул сервер, показан, даже если в таблице связей старое поле отзыва не пустое.
- **К8. Поля.** Имя, группа и название группы берутся из ответа; ребёнок без группы остаётся «без группы» (Schedule: отдельная строка, Home: без названия группы).
- **К9. Пустой список ≠ ошибка.** Успешный пустой ответ даёт прежние состояния «нет детей» (Home: шаги подключения; Schedule: «связь не подтверждена»; Календарь: прежнее пустое состояние).
- **К10. Ошибка и сбой сети** (ответ с ошибкой, Promise.reject): понятная ошибка без сырого текста и с «Повторить» там, где она была; вечной загрузки и ложного «нет детей» нет.
- **К11. Прочее не меняется.** Запросы матчей, заявок на связь, расписания, событий; права, суммы, RLS. Порядок детей в календаре теперь по имени (раньше по id связи): выбранный ребёнок по умолчанию — первый по имени.

Проверки: расширенный `MyChildrenSource.test.tsx` (К7-К10), `Home.test.tsx` (ошибка через `my_children`), весь веб-набор `npx vitest run`, `tsc --noEmit`, `npm run build` на итоговом дереве, Node-тесты CI.
Независимой проверки второй моделью нет (решение владельца 2026-11-11).
