# Условия приёмки: #471 PR-2b, перенос исторических остатков `opening_balance` (миграция 0189, 13.11.2026)

Задача: Issue #471, план v5, раздел 3.3 и T9. Требует применённой 0188. Миграцию данных запускает только владелец, после выгрузки `db/ops/readonly-eq-baseline-471.sql` (раздел «2 журнал»).

## Состав
- `db/migrations/0189_equipment_opening_balance.sql`, строка в `db/ops/preflight.sql`, откат `db/ops/rollback-0189-equipment-opening-balance.sql`.
- `db/tests/rls_eq471_opening_balance_test.sql`.

## Условия
**О1. Дельта.** Для каждого заказа `дельта = paid − сумма журнала экипировки заказа`.
**О2. `дельта > 0`.** Вставляется одна строка `opening_balance` на сумму дельты, без автора, `kind = equipment`; дата: дата заказа, иначе первая дата журнала экипировки по заказу, иначе дата создания заказа (T9). Подпись «Внесено до начала учёта в приложении».
**О3. `дельта = 0`.** Ничего не добавляется.
**О4. `дельта < 0`** (журнал больше `paid`): ничего не правится, миграция останавливается (ошибка со списком заказов, их `paid` и суммой журнала), вся транзакция откатывается; разбирает владелец.
**О5. Самопроверка.** После вставки в той же транзакции: для каждого заказа `paid = сумма журнала`; суммы `paid` и `total` по заказам не изменились; сумма вставленных строк равна «paid > суммы журнала» из выгрузки PR-0 («2 журнал»); сумма «касса» (без `opening_balance`) не изменилась. Любое расхождение откатывает транзакцию.
**О6. Служебный признак.** `eq.backfill_gate = 'on'` ставится только на время транзакции миграции (`set local`) и после неё не остаётся.
**О7. Повторный запуск.** Повторное применение не добавляет строк (после первого запуска дельта у всех заказов 0).
**О8. Кассовые отчёты.** `cash_report` и `cash_day_service` после миграции дают те же числа, что до (строки `opening_balance` исключены).
