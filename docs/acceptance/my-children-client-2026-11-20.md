# Условия приёмки: экраны родителя берут детей из `my_children()` (PR 2, клиент)

Серверная часть: миграция 0215 (#782), условия `docs/acceptance/my-children-2026-11-20.md`. Миграций и серверных изменений в этом PR нет.
Выкладывать на деплой только после применения 0215 в проде (без функции экраны покажут понятную ошибку с повтором).

Экраны: «Запись» (Booking), «Матчи», «Оплата», «Мои дети», счётчик детей в App (стартовая вкладка, вкладка «Ребёнок»).

- **К1. Источник.** Список детей берётся вызовом `my_children()`; таблица `player_guardians` этими экранами не читается; клиентский фильтр по полю отзыва старой модели убран.
  Ребёнок, которого сервер вернул, показан, даже если в таблице связей старое поле отзыва не пустое; ребёнок, которого сервер не вернул, не показан.
- **К2. Пустой список ≠ ошибка.** Успешный пустой ответ даёт прежнее состояние «нет детей»; ошибки там нет.
- **К3. Ошибка и сбой сети** (ответ с ошибкой, отклонённый запрос): экран показывает понятную ошибку с «Повторить», без сырого текста (имя функции, код); ложного «нет детей» нет; повтор восстанавливает экран. Для Booking это уже было (#777) и сохраняется.
- **К4. Поля.** Имя и группа (`group_name`) берутся из ответа; ребёнок без группы остаётся «без группы» (Матчи, Мои дети).
- **К5. App.** Вкладка «Ребёнок» и стартовая вкладка определяются по длине ответа `my_children()`; ошибка списка не открывает вкладку «Ребёнок» (как прежде при ошибке счётчика).
- **К6. Остальное не меняется.** Права, суммы, RLS, другие экраны, читающие `player_guardians` (Home, Schedule, ParentCalendar, ParentCamps), в этот PR не входят.

Проверки: `web/src/screens/MyChildrenSource.test.tsx` (К1-К5), обновлённые `Booking.test.tsx` и `App.test.tsx`, полный веб-набор `npx vitest run`, `tsc --noEmit`, `npm run build`.
Независимой проверки второй моделью нет (решение владельца 2026-11-11).
