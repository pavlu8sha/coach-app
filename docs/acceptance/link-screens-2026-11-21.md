# Привязка ребёнка: согласие после подтверждения, имя в запросе, правки экранов (скрины Павла 20.11)

Условия приёмки. Тесты пишутся от них: `db/tests/rls_link_screens_test.sql` (номера С1-С12), `web/src/screens/LinkScreens.test.tsx`, `web/src/screens/ConsentAccept.test.tsx`, `web/src/screens/Schedule.test.tsx`, `web/src/screens/About.test.tsx`, `web/src/screens/TrialForm.test.tsx`.
Миграция 0217 только добавляет две функции чтения. Существующие функции, RLS, таблицы и права не меняются. Режим согласий `consent.mode=all` не включается (#787).

## Что увидел Павел
1. Запрос подтверждён, а ребёнок не виден («Ребёнок пока не отображается»). Причина: у родителя из `consent_test_parents` (режим test) доступ даёт только действующее согласие новой модели; `decide_link` его не создаёт, экрана принятия в приложении нет, `my_children()` честно возвращает пусто.
2. В «Статусе привязки» вместо имени «Игрок»: до подтверждения родитель не видит строку ребёнка (RLS), вложенный выбор `players(full_name)` возвращает null.
3. В «Добавить ребёнка» кнопка «Отправить запрос» доступна без согласия, плашка «Выбрано» стоит под группой как статус.
4. Расписание у гостя: «появится, когда администратор подтвердит связь с ребёнком».
5. Роль «Ребёнок»: кнопка «Написать администратору» на «О клубе» не нужна.
6. Заявка на пробную тренировку: кнопка серая, причина не названа (год рождения 2003 вне допустимого диапазона).

## Условия приёмки

### База (миграция 0217, только чтение)
- **С1.** `my_link_requests()` возвращает запросы только вызывающего (id, status, player_id, full_name, group_name), новые первыми; чужие запросы не видны; без входа `forbidden`.
- **С2.** Имя ребёнка возвращается и в статусе `pending`, когда прямой выбор `players` родителю его не отдаёт (RLS не ослаблена, прямое чтение чужого `players` по-прежнему пусто).
- **С3.** `my_pending_consents()`: для родителя режима test (или всех при `all`) со связью без действующего согласия возвращает ребёнка (player_id, full_name, group_name, version_id, version) и текущую версию `data_processing`.
- **С4.** Пусто, если: режим off; родитель вне `consent_test_parents` в режиме test; согласие уже действует (текущая версия); нет текущей версии согласия; согласие отозвано родителем или администратором (источник не `system`): отозванное намеренно предложением не возвращается.
- **С5.** Возвращает ребёнка, если согласие принято по старой версии (нужна новая) или снято системой при создании связи (`source = 'system'`).
- **С6.** Чужие связи не видны. Без входа `forbidden`.
- **С7.** После `accept_consent(p, 'data_processing', version_id)` из результата `my_pending_consents()` ребёнок исчезает, а `my_children()` его возвращает (сквозной путь «подтверждён → принял → виден»).
- **С8.** Права: `execute` у `authenticated`, нет у `anon` и `public`; проверка на базе с привилегиями по умолчанию Supabase (`alter default privileges ... grant ... to anon, authenticated, service_role`).
- **С9.** Строка preflight 0217 есть, на базе без 0217 даёт NOT_APPLIED (через `to_regprocedure`), на полной APPLIED.

### Приложение
- **С10 (имя).** «Статус привязки», главная (ожидание) и экран поиска показывают имя ребёнка из `my_link_requests()`. Если функции в базе ещё нет («Could not find the function»), экран работает как раньше (прямой выбор), без ошибки пользователю.
- **С11 (согласие).** Если детей нет, а `my_pending_consents()` не пуст, вместо «Ребёнок пока не отображается» показывается экран «Примите согласие»: имя ребёнка, ссылка на правила (`Privacy`), галочка. Кнопка «Принять согласие» (нативная Telegram или обычная) видна и активна только при отмеченной галочке. Нажатие вызывает `accept_consent(player_id, 'data_processing', version_id)`, затем список обновляется и ребёнок появляется. Ошибки только через `errMsg`, кнопка не зависает при сбое. Если функции нет в базе, показывается прежний экран «Ребёнок пока не отображается».
- **С12 (поиск).** «Выбрано» убрана из-под группы: выбранная строка подсвечена, справа галочка вместо стрелки, `aria-pressed`/`aria-current` выставлены. Нативная кнопка Telegram «Отправить запрос» не показывается, пока галочка согласия не отмечена; при отметке появляется, снятие галочки снова скрывает. В браузере обычная кнопка остаётся видимой, но неактивной до отметки.
- **С13 (Расписание).** Гость, ребёнок и любой экран `all` без групп: «Расписание групп пока не опубликовано. Загляните позже.» (без «подтверждения связи»). Родитель с запросом/без: прежний текст про связь остаётся.
- **С14 («О клубе»).** Для роли `child` кнопки «Написать администратору» нет (ни в шапке, ни в нижней ссылке раздела); для guest и parent остаётся.
- **С15 (заявка на пробную).** Под формой при неверных данных перечислено, чего не хватает (имя родителя, имя ребёнка, год рождения «от {YEAR-18} до {YEAR-2}», телефон, согласие). Кнопка «Отправить заявку» активна ровно когда подсказок нет. Нативная кнопка Telegram не добавляется.

## Не входит
Автоматическое принятие согласия за родителя при подтверждении (юридически отдельное согласие, решение владельца: только своё действие родителя). Включение `consent.mode=all`. Правка `decide_link`, `parent_access_ok`, `my_children`. Данные прода не трогаются.

## Применение
Миграцию 0217 применяет Павел после свежего `db/ops/preflight.sql`; без неё приложение работает как сегодня (имя «Игрок», экран про согласие не появляется). Версия текста согласия для тестового родителя: `db/ops` скрипты consent-238 уже заводят тестовую версию; если текущей версии `data_processing` нет, экран согласия не показывается (С4).
