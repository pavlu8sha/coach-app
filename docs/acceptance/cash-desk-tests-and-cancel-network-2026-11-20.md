# Приём оплат: покрытие тестами смены способа и сбой связи при отмене (2026-11-20)

Продолжение PR #781 (LOW-замечание к тестам и найденная та же уязвимость в «Отменить оплату»). Без миграций, SQL и изменения сумм.

Условия приёмки:
1. Тестовый fake `update` применяет значения к строкам под фильтром без мутации исходных объектов (фикстуры общие между тестами), с `.select()` возвращает изменённые строки; пустой результат моделируется фильтром без совпадений.
2. Тест успеха смены способа: после правки и перечитывания строка показывает новый способ, плитки «Наличные»/«Перевод» за день пересчитаны (50 ₾ переходят из «Перевод» в «Наличные»).
3. Тест нулевого результата: оплату уже изменили до подтверждения → сообщение «Способ не изменён: оплата уже изменена или нет прав», оплата не тронута.
4. Тест ошибки базы остаётся отдельным.
5. «Отменить оплату»: сбой связи (rejected promise) даёт сообщение «Отмена не записана… отмена могла примениться», блокировка снимается, список перечитывается, повторная отмена после «Повторить» работает.
