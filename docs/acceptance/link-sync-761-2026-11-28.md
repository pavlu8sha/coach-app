# Привязка ребёнка: синхронизация связей, согласий и статусов родителя (#761)

Условия приёмки. Тесты пишутся от них: `web/src/screens/Home.test.tsx`, `Link.test.tsx`, `LinkOnboarding.test.tsx`, `LinkStatus.test.tsx`, `MyKids.test.tsx`.
Только клиент. RPC, RLS, миграции, модель согласий, бизнес-правила привязки, сроки retry и лимиты не меняются. #730 не входит.

## Исходное состояние (master a16f3fd)
- `consent_revoked_at` в рабочем коде экранов уже не используется: Home и MyKids читают `my_children()` (0215). Остаётся закрепить это тестом.
- Home: сбой `my_link_requests` превращается в ошибку всего экрана, даже если дети уже загружены.
- Link: после успешного `request_link` сбой `loadReqs()` выглядит как ошибка отправки.
- LinkOnboarding: при «подтверждён, ребёнка нет» совет «закройте приложение и откройте снова», кнопки обновления нет.
- LinkStatus: «Подтверждено» безусловно пишет «Ребёнок привязан и виден на вкладке».

## Условия
**A. Критерий доступа (LINK-CLIENT-01)**
1. Связь с заполненным старым `consent_revoked_at`, которую сервер отдаёт в `my_children()`, показывается в Home и MyKids.
2. Связь, которую сервер не отдаёт (`my_children()` пуст), не показывается, даже если старое поле пустое. Клиент доступ сам не восстанавливает.

**B. Home и `link_requests` (LINK-CLIENT-02)**
3. Сбой чтения запросов при загруженных детях: дети остаются на экране; рядом блок с предупреждением и кнопкой «Повторить загрузку»; список запросов не выдаётся за пустой.
4. Сбой чтения запросов при отсутствии детей: ошибка с повтором, а не онбординг «Подключите профиль ребёнка».
5. Повтор после успеха убирает предупреждение и показывает запросы. Ответ устаревшей загрузки (после повтора или ухода с экрана) не применяется: флаг `cancelled` в загрузке (проверяется ревью кода, отдельного теста нет).

**C. Link после `request_link` (LINK-CLIENT-03)**
6. `request_link` успешен, обновление списка не удалось: пользователь видит «Запрос отправлен, но список статусов пока не обновился» (не ошибка отправки, без красного класса `error`); в статус не переходим; кнопка «Обновить статусы».
7. Повтор успешен: сообщение снято, открывается статус.
8. `request_link` отклонён: показывается ошибка отправки, как раньше; сообщение «Запрос отправлен» не показывается.

**D. Онбординг при approved (LINK-CLIENT-04)**
9. Гонка: связи прочитаны до одобрения, запросы после. Home читает запросы раньше связей, а при «одобрен, детей нет» один раз перечитывает связи; ребёнок появляется без перезапуска.
10. Если после повтора детей всё ещё нет: экран «Ребёнок пока не отображается» с кнопкой «Проверить снова» (на время проверки «Проверяю…», недоступна), без совета перезапускать приложение. После проверки без результата: «Проверили: ребёнок пока не отображается».
11. «Проверить снова» перечитывает связи и запросы; если сервер уже отдаёт ребёнка, показывается карточка.

**E. LinkStatus (текст = фактический доступ)**
12. Одобренный запрос, ребёнок есть в `my_children()` (по `player_id`, при его отсутствии по имени): «Ребёнок привязан и виден на вкладке «Ребёнок»».
13. Одобренный запрос, ребёнок ждёт согласия (`my_pending_consents()`): «Осталось принять согласие».
14. Одобренный запрос, ребёнка нет ни там, ни там: «Запрос подтверждён, но ребёнок пока не отображается», кнопка «Проверить снова», без утверждения «виден».
15. Сбой проверки доступа (children/consents): статусы всё равно показываются; для одобренного нейтральный текст «Не удалось проверить» и «Проверить снова». Список запросов не блокируется.
16. Ожидающий и отклонённый тексты не меняются.

## Не входит / ограничения
- Сервер: `request_link`/`retry_link` при неактивной версии согласия и `cancel_link` не меняются; серверные тесты этих контрактов не добавляются в этот PR, если уже есть (проверка в описании PR).
- Вёрстка проверяется в Chromium на 320/375/430, светлая и тёмная темы; iPhone за Павлом.
