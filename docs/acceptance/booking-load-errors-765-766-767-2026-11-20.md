# Условия приёмки: ошибки загрузки и проверки на экране «Запись» родителя (#765, #766, #767)

Источник: независимый аудит #718 (сценарий №4), Issues #765, #766, #767. Master `22ac226`.
Область: только `web/src/screens/Booking.tsx` и `web/src/screens/Booking.test.tsx`. Не меняются: RPC `booking_board`, `booking_signup`, `booking_conflicts`, `waitlist_*`, RLS, права, схема, миграции, продуктовые правила записи и очереди, админская запись (`bookingClash.ts`).
Общее: пользователю показываются только понятные тексты (`errMsg`, `fallbackError`), сырое сообщение Supabase не показывается (сторожевой тест `UserErrors.test.tsx`).

## #765. Связанные дети

Состояния: загрузка, успешно пустой список, успешно непустой список, ошибка.

1. **Непустой список.** Кнопки записи у допущенных детей как раньше, блока ошибки нет.
2. **Успешный пустой список.** Блока ошибки нет; показывается нейтральная строка «К профилю не привязан ни один ребёнок, записывать некого». Кнопок записи нет.
3. **Ошибка Supabase (`player_guardians`).** Блок `role="alert"` «Не удалось загрузить список детей» с понятным текстом и кнопкой «Повторить». Строка «не привязан ни один ребёнок» НЕ показывается (состояние неизвестно). Кнопок записи, отмены и очереди нет. Занятия (карточки) видны.
4. **Rejected promise** при чтении `player_guardians` (сбой сети, исключение): то же, что в п. 3.
5. **Повтор.** «Повторить» заново читает `player_guardians`; после успеха блок исчезает, кнопки записи появляются.
6. **Нет пользователя** (`getUser` без пользователя): как на сервере (`booking_board` без пользователя отвечает `forbidden`, миграция 0045) показывается полноэкранное «Не удалось загрузить занятия» с повтором; `player_guardians` и `booking_board` не вызываются, карточек и кнопок записи нет.
7. **Устаревший ответ.** Если загрузка запущена повторно, результат более ранней не применяется (в том числе ранняя ошибка не затирает успех и ранний успех не затирает последнюю ошибку).
8. **Смена пользователя.** При событии `onAuthStateChange` с другим пользователем состояние сбрасывается и загрузка выполняется заново; ответ прежнего пользователя не применяется. То же событие с тем же пользователем (обновление токена) загрузку не перезапускает.
9. **Ошибка `booking_board` и пустая доска** ведут себя как раньше (полноэкранное «Не удалось загрузить занятия» с повтором; «Занятий для записи пока нет»). Отказ `booking_board` через rejected promise тоже даёт полноэкранную ошибку, а не вечную загрузку.
10. **Отозванное согласие.** Фильтр `consent_revoked_at is null` сохраняется (доступ не расширяется): ребёнок с отозванным согласием в список не попадает. Вывод по соответствию `parent_access_ok()` / `is_guardian_of()` оформлен в описании PR; серверная модель не менялась.

## #766. Очередь ожидания

11. **Успешная пустая очередь.** Ребёнок вне очереди при `Мест нет`: «Встать в очередь», при свободных местах «Записать» — как раньше.
12. **Позиция.** При успехе «В очереди: N из M», «Выйти из очереди» — как раньше.
13. **Предложение места.** «Есть место», «Занять место» — как раньше.
14. **Ошибка `waitlist_board`** (Supabase error или rejected promise). Блок `role="alert"` «Не удалось загрузить очередь ожидания» с пояснением и «Повторить». Для ребёнка, не записанного на занятие, не показываются «Встать в очередь» и «Записать» (состояние очереди неизвестно). `waitlist_join` и `booking_signup` не вызываются. Уже записанным детям «Отменить запись» остаётся (запись известна из `booking_board`).
15. **Повтор после ошибки** показывает позицию или предложение места; блок ошибки исчезает; «Встать в очередь» для ребёнка в очереди не появляется.
16. **Функция очереди не установлена** (до 0149) теперь тоже ошибка с повтором, а не «очереди нет»: 0149 применена в проде, молчаливый режим больше не нужен.
17. Серверная семантика (дубль `(session_id, player_id)`, `waitlist_join`/`leave`/`claim`, текст «место успел занять другой родитель») не меняется; существующие тесты сохранены.

## #767. Проверка пересечений

Правило не меняется: пересечение времени предупреждает, но не запрещает запись.

18. **Нет пересечений.** После успешной проверки `booking_signup` вызывается как раньше, один раз.
19. **Есть пересечение.** Прежнее предупреждение «В это время у … уже есть: …» и «Всё равно записать»; без подтверждения `booking_signup` не вызывается; после подтверждения вызывается ровно один раз; «Не записывать» закрывает без записи.
20. **Ошибка проверки** (Supabase error, отказ доступа, функция не найдена, rejected promise): `booking_signup` НЕ вызывается автоматически. Блок `role="alert"`: «Не удалось проверить, есть ли у {имя} другие занятия в это время» и три действия: «Повторить проверку», «Продолжить без проверки», «Не записывать».
21. **«Продолжить без проверки»** вызывает `booking_signup` ровно один раз; повторные быстрые нажатия не создают второго вызова.
22. **«Не записывать»** закрывает блок; запись не создаётся.
23. **«Повторить проверку»** вызывает `booking_conflicts` снова: успех без пересечений продолжает запись (как п. 18), успех с пересечением показывает предупреждение (п. 19), новая ошибка снова показывает три действия без записи.
24. **Двойное нажатие «Записать»** во время проверки не запускает вторую проверку и вторую запись.
25. Если `booking_signup` после явного продолжения вернул ошибку, показывается понятный текст, как для обычной записи.
