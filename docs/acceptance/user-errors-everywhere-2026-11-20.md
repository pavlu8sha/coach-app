# Понятные ошибки на всех экранах (продолжение #705)

Условия приёмки. Тесты пишутся от них: `web/src/lib/userError.test.ts`, `web/src/lib/safeFetch.test.ts`, `web/src/lib/coach.test.ts`, `web/src/noRawErrors.test.ts` (сторожевой тест по исходникам), `web/src/App.test.tsx`.
Решение владельца (2026-11-20): не оставлять экраны с сырыми ошибками, исправить везде, а не только на трёх экранах из #756.

## Проблема
- В 58 файлах ответ базы показывается пользователю как есть: `setError(r.error.message)` (около 100 мест) и мапперы с сырым запасным вариантом (`coachError`, `clubEventErr`, `rsvpError`, `errText` в `photos.tsx`, `loadErr` в `AdminArticles.tsx`). Сетевой сбой приходит от supabase-js как ответ с ошибкой (`TypeError: Failed to fetch`), его пользователь видит сырым.
- Вход в приложение (`App.tsx`, `lib/auth.ts`) показывает `e.message` и технические коды (`users_insert: …`).
- Ответ может прийти и как отклонённый Promise (сбой `fetch` вне PostgREST: вход, Edge Functions, хранилище): кнопки с `busy` зависают.

## Условия приёмки
1. Ни один экран не показывает пользователю сырое сообщение Supabase/SQL/сети, имена функций, SQLSTATE, `stack`. Ожидаемые ошибки показываются прежними понятными текстами (мапперы экранов не меняются).
2. `coachError` и остальные мапперы на неизвестном тексте возвращают: «Нет связи. Проверьте интернет и попробуйте ещё раз.» для сетевых сбоев, «Не удалось выполнить действие. Попробуйте ещё раз.» для остального. Сообщения базы на русском (написанные для пользователя) проходят как есть. Сырой текст пишется только в `console.error`.
3. Новый `errMsg(error)` (в `lib/coach.ts`) — единая точка для ответа `{ error }`: все прежние `setX(r.error.message)` используют её.
4. Любой отказ `fetch` внутри supabase-js (в том числе вход, хранилище, функции) превращается в ответ с ошибкой «Нет связи…», а не в отклонённый Promise; отмена запроса (`AbortError`) остаётся отменой. Поэтому `busy` на экранах не зависает при сетевом сбое.
5. Вход (`App.tsx`): при ошибке входа показывается понятный текст («Не удалось войти. Откройте приложение заново.»; лимит попыток — прежний текст), коды и подробности только в журнал.
6. Сторожевой тест по исходникам падает, если в коде экрана появляется сырой вывод `.error.message`, `e.message` или мапперы с сырым запасным вариантом.
7. Поведение при успехе, права, RLS, SQL не меняются. Миграций нет.

## Не входит
Тексты самих мапперов и сообщений, написанных на русском вручную; рефакторинг экранов; `try/finally` в каждом из 91 обработчика с `busy` (п. 4 закрывает причину централизованно).
