# Условия приёмки: статус привязки ребёнка в «Мои дети» (#735)

Источник: аудит #693 (этап «Профиль», 19.11.2026), Issue #735. Master `adefdc3`.
Область: `web/src/screens/MyKids.tsx` и его тесты (`MyData.test.tsx` содержит прежний тест «Мои дети», новые тесты в `MyKids.test.tsx`). Не меняются: правила привязки, `create_child_code`, `unlink_child`, `revoke_consent`, `child_linked`, RLS, данные, остальное содержимое экрана («Отозвать согласие», добавление ребёнка, статусы запросов).

## Проблема
После загрузки списка детей `child_linked` проверялся для каждого ребёнка отдельно, а до ответа набор `linkedKids` был пустым: уже привязанному ребёнку на время проверки показывалось «Код для ребёнка», и нажатие вызывало лишний `create_child_code`. Ошибка `child_linked` считалась «нет привязки» (`data === true ? … : null`).

## Условия
1. **Четыре состояния на ребёнка:** `loading`, `linked`, `free` (не привязан), `error`. Состояния независимы: ответ или сбой по одному ребёнку не влияет на другого.
2. **loading.** Действий «Код для ребёнка» и «Отвязать аккаунт ребёнка» нет; показывается «Проверяю привязку аккаунта…» (`role="status"`).
3. **linked** (`data === true`). Показывается только «Отвязать аккаунт ребёнка»; «Код для ребёнка» нет.
4. **free** (`data === false`). Показывается «Код для ребёнка»; «Отвязать…» нет.
5. **error** (ошибка RPC или ответ не `true`/`false`). Показывается безопасное сообщение без технического текста («Не удалось проверить привязку аккаунта ребёнка…», `role="alert"`) и кнопка «Повторить проверку». Ни «Код для ребёнка», ни «Отвязать…» не показываются: ошибка не равна «не привязан».
6. **Повтор.** «Повторить проверку» заново вызывает `child_linked` только для этого ребёнка; пока идёт запрос, состояние `loading`. После успешного ответа показывается действие по условиям 3 или 4.
7. **Защита от преждевременного нажатия.** `create_child_code` вызывается только в состоянии `free`, `unlink_child` только в `linked`; кнопок в остальных состояниях нет, а обработчики дополнительно проверяют состояние.
8. **Устаревшие ответы и перезагрузка списка.** Ответ проверки, запущенной раньше (после перезагрузки списка или повтора), не применяется поверх более нового. С началом новой загрузки списка статусы прежнего списка недействительны: у всех детей снова `loading` (действий нет, обработчики не вызывают RPC), пока не придут новые ответы.
8а. **StrictMode.** Повторный запуск эффектов (`setup → cleanup → setup`) не отключает применение ответов: проверка доходит до `linked`/`free`.
9. **Выданный код.** Показ выданного в этой сессии кода не меняется (как раньше имеет приоритет над кнопками).
10. **Не меняется:** «Отозвать согласие» доступно всегда, как раньше; ошибка загрузки списка детей; пустое состояние; добавление ребёнка.

## Проверки (Vitest, `MyKids.test.tsx`)
Загрузка (2, 7); true (3); false (4); ошибка RPC и ответ `null` без ошибки (5); повтор с успехом (6); несколько детей: один linked, второй ещё грузится, третий с ошибкой (1); нажатие невозможно до ответа и `create_child_code` не вызывается (7); перезагрузка списка и устаревший ответ (8); сброс статусов при зависшей перезагрузке списка (8); StrictMode (8а); код и «Отозвать согласие» (9, 10).

## Вне #735
Правила привязки, генерация кодов, отзыв согласия, RPC, RLS, данные; другие пункты аудита «Профиль».
