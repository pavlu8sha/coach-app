# Условия приёмки: «Матчи» — «+ Матч» в шапке и меню «⋯» (дизайн-система, PR 3)

Источник: решение Павла 19.11 («согласен с предложениями», раздел 3 макетов `ds-improvements.html`), план `implementation-plan-2026-11-19.md`. Master `4c884f0`.
Область: `web/src/screens/CoachMatches.tsx` (только список), новый `web/src/ui/MoreMenu.tsx`, `web/src/ui/kit.css`, тесты. Не меняются: загрузка данных (новых запросов нет), права (кто видит «Новое событие»), окно выбора «Добавить матч» и его содержимое, форма матча, события, экран «Матчи с подтверждением», список матчей и фильтр команды, миграции, данные.

## Условия
1. **«+ Матч» в шапке.** Рядом с заголовком «Матчи» малая кнопка «+ Матч»; открывает то же окно выбора, что раньше называлось «Добавить матч» (`aria-label` карточки «Добавить матч» сохраняется). В теле экрана больших кнопок «Добавить матч», «Новое событие», «Матчи с подтверждением» больше нет.
2. **Меню «⋯».** В шапке рядом с «+ Матч» кнопка «⋯» (`aria-label` «Ещё», `aria-haspopup="menu"`, `aria-expanded`). Открывает меню с пунктами: «Новое событие» (только администратор, как раньше) и «Матчи с подтверждением». Пункты — `role="menuitem"`, нажимаемая область ≥ 44 px. Нажатие на пункт выполняет прежнее действие (открывает событие/экран подтверждения) и закрывает меню.
3. **Счётчик.** Пункт «Матчи с подтверждением» показывает число предстоящих опубликованных матчей с подтверждением, посчитанное из уже загруженных данных (`lifecycle_status = published`, начало в будущем); при нуле счётчика нет; на кнопке «⋯» тоже точка/число, если счётчик больше нуля (`aria-label` кнопки: «Ещё, N»). Новых запросов нет.
4. **Закрытие меню.** Esc, нажатие вне меню и повторное нажатие на «⋯» закрывают меню. При Esc, повторном нажатии и выборе пункта фокус возвращается на «⋯». При нажатии вне меню фокус не отбирается: он остаётся там, куда пришёлся клик (другая кнопка или поле), иначе меню перехватывало бы фокус у нажатого элемента. Меню не уводит страницу в горизонтальную прокрутку на 320–430 px; светлая и тёмная тема; не только цвет несёт смысл (текст пунктов).
5. **Сохранённое поведение.** Окно «Добавить матч» (события и команды), выбор команды, форма, список, фильтр команды, права администратора и тренеров без изменений.
6. Остальные экраны не затрагиваются.

## Проверки (автотесты, Vitest)
Кнопка «+ Матч» открывает окно «Добавить матч» (1); нет прежних больших кнопок (1); «⋯» открывает меню; администратор видит «Новое событие», тренер нет (2); пункты ведут на прежние экраны и закрывают меню (2); счётчик по предстоящим опубликованным матчам с подтверждением, без него при нуле (3); Esc, клик вне (в том числе касание), повторный клик закрывают; фокус возвращается на «⋯» после Esc и выбора пункта, а после клика вне остаётся на нажатом элементе (4); существующие тесты окна «Добавить матч» проходят с новой кнопкой (5). Полный `npx vitest run`, `tsc`, `npm run build`.

## Честно о проверках
Независимой проверки второй моделью не было (решение владельца 2026-11-11). Миграций нет. Что считать «ожидающими» в счётчике, макет не уточнял; взято «предстоящие опубликованные матчи с подтверждением» из уже загруженных данных, это можно поменять отдельным решением.
