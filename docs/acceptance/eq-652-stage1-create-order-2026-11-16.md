## Условия

**Ч1. Сигнатура.** `eq_create_order(p, lines, insc, num, inst, loc, custom_total default null, req default null)`. Старая семиаргументная версия удалена (двух перегрузок нет), вызовы с семью аргументами, в том числе по именам из PostgREST, работают.

**Ч2. Повтор с тем же ключом.** Тот же вошедший пользователь и тот же `req` для того же игрока с теми же строками (название, размер, количество) возвращает id уже созданного заказа. Новых заказов, строк, событий и записей истории не появляется, итог и `paid` не меняются.

**Ч3. Тот же ключ для другого запроса.** Другой игрок или другой состав строк: `request id reused` (`22023`), ничего не создаётся.

**Ч4. Ключ принадлежит автору.** Другой администратор с тем же `req` создаёт свой заказ (ключ уникален в паре автор + ключ, индекс из 0185).

**Ч5. Без ключа поведение прежнее.** Каждый вызов создаёт новый заказ; цены по каталогу; `custom_total` заменяет итог.

**Ч6. Параллельные повторы.** Несколько одновременных вызовов с одним ключом дают ровно один заказ, все получают один и тот же id, ошибок нет (нарушение уникальности перехватывается и разрешается возвратом существующего заказа).

**Ч7. Атомарность и повтор после ошибки.** Ошибка в любой строке (`kit not in catalog`, `bad quantity`) не оставляет ни заказа, ни строк; повтор с тем же ключом после исправления проходит как новый запрос.

**Ч8. Проверка входных данных.** `lines` — непустой массив объектов; количество — целое от 1 до 10 (`bad quantity`, `22023`), как в `eq_edit_line`; отсутствие количества означает 1; `custom_total < 0` отклоняется как раньше.

**Ч9. Права не меняются.** Вызывает только глобальный администратор (`forbidden`, `42501` у остальных, включая локального администратора и родителя). У `anon` права на выполнение нет, у `authenticated` есть. Проверено на базе с привилегиями по умолчанию Supabase (`alter default privileges ... grant execute ... to anon, authenticated, service_role`), а не только без них.

**Ч10. Клиент.** «Новый заказ» создаёт ключ при открытии формы, отправляет его в каждом вызове, сохраняет при ошибке и повторном нажатии и меняет только после успешного создания. Двойное нажатие даёт один вызов (кнопка недоступна, пока идёт запрос).

**Ч11. Существующий административный сценарий.** Все прежние тесты зелёные: `rls_equipment_admin_test.sql`, `rls_eq471_*`, `rls_definer_hardening_test.sql`, `Equipment.test.tsx`, preflight (на полной базе только APPLIED).

**Ч12. Откат.** Откат возвращает семиаргументную версию из 0102 с правами из 0036; заказы, созданные с ключом, сохраняются.
