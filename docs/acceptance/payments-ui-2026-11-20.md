# Условия приёмки: экран «Оплаты» (2026-11-20)

План: `implementation-plan-2026-11-19.md`, экран 4. Только клиент, миграций нет.
Деньги не меняются: те же запросы, те же записи с минусом, те же подтверждения.

1. **Вкладки в один ряд.** Раздел «Оплаты» администратора (`Money`): четыре
   вкладки («Приём оплат», «По месяцам», «Должники», «Отчёт») стоят в одном ряду
   на ширине 320, 360 и 390 px, без второй строки. Если не помещаются, ряд
   прокручивается внутри себя, страница по горизонтали не прокручивается.
   Остальные переключатели (`Segmented`) не меняются.
2. **Быстрые даты.** В «Приёме оплат» над полем даты есть кнопки «Сегодня» и
   «Вчера». Выбранная нажата (`aria-pressed`). Поле даты остаётся для любой
   другой даты и не позволяет выбрать будущее. «Вчера» — предыдущий день от «сегодня»
   (`today()`, местная дата телефона, как и сейчас).
3. **Отмена через «⋯».** Строка оплаты абонемента, которую можно отменить, не
   имеет отдельной кнопки «Отменить оплату». У строки есть кнопка «⋯»
   (доступное имя «Действия: <имя игрока>») с пунктом «Отменить оплату».
   Пункт открывает прежнее окно подтверждения «Отменить оплату?» с теми же
   строками и текстом. Без подтверждения запись не создаётся.
4. У отменённых оплат, отрицательных записей, сборов, экипировки и занятий
   меню нет (как раньше кнопки не было).
5. Пока идёт отмена, повторный выбор пункта не отправляет второй запрос (как раньше у кнопки).
6. Подсказка под списком обновлена: «Отменить можно оплату абонемента через «⋯»
   у строки; остальные оплаты отменяются в своих разделах».
7. Меню «⋯» строки не обрезается краем карточки и не уходит за экран
   (проверка отрисовкой в Chromium на 390 px; iPhone за владельцем).
8. Все существующие тесты кассы и отмены остаются зелёными с заменой действия
   «нажать кнопку» на «открыть ⋯ и выбрать пункт».
