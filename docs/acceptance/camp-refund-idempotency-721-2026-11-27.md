# Условия приёмки: идемпотентность возврата за сбор (#721, миграция 0231)

Повтор `camp_refund` после таймаута или потери ответа не должен создавать второй возврат и второй раз уменьшать оплаченное.
Суммы, тарифы, правила «возврат не больше оплаченного», права, история сборов и RLS не меняются.
Образец: 0214 (#724, платежи абонемента), `docs/acceptance/payment-idempotency-724-2026-11-20.md`.

## Модель

- В `camp_payments` добавляется `request_id uuid` и уникальный частичный индекс `(recorded_by, request_id) where request_id is not null`.
  Ключ задаёт клиент; автор берётся из сессии (триггер `stamp_payment_author`). Старые строки остаются с `null`.
- Функция `camp_refund(pid, amt, d, cmt, req uuid default null)` возвращает `jsonb {id, duplicate}` (раньше `uuid`).
  Прежняя четырёхаргументная функция удаляется (иначе вызов без ключа остался бы вторым путём с неоднозначным выбором перегрузки).
- Порядок внутри функции: проверка администратора, блокировки сбор → участник (как раньше), затем поиск записи с этим ключом
  и только потом проверки суммы. Повтор успешного возврата всего остатка не должен упасть на «refund above paid».
- Вставка с `on conflict (recorded_by, request_id) do nothing`: защита на уровне PostgreSQL, не только блокировкой и не только UI.
- `req is null`: поведение как до миграции (без защиты от повтора). Нужно, чтобы старая версия интерфейса работала в окне между миграцией и деплоем.
  Интерфейс после деплоя всегда передаёт ключ.

## Условия

1. **Обычный возврат.** Новый ключ: одна строка `refund` с минусом (как раньше), `duplicate = false`, `id` строки.
2. **Повтор того же запроса.** Тот же автор, ключ, участник, сумма (и комментарий; дата, если передана): новых строк нет, возвращается `id` первой строки,
   `duplicate = true`, ошибки нет, оплаченное не меняется.
3. **Повтор после возврата всего остатка** (оплачено 1000, возврат 1000, повтор): `duplicate = true`, а не `refund above paid`.
4. **Потерянный ответ:** первая запись зафиксирована, клиент повторил: результат как в п. 2.
5. **Параллельные запросы с одним ключом** (отдельные сессии, одновременно): одна строка `refund`, один ответ `duplicate = false`, остальные `duplicate = true`, ошибок нет; оплаченное уменьшено один раз.
6. **Ключ с другим содержимым** (другой участник, сумма, комментарий; дата, если передана): `request id reused` (22023), строк не добавляется.
7. **Самостоятельные возвраты.** Два возврата с разными ключами и одинаковыми участником, суммой, датой и комментарием записываются оба
   (если оплаченного хватает), в том числе параллельно. Возврат без ключа повторяется как раньше.
8. **Ключ принадлежит автору.** Другой администратор с тем же ключом создаёт свою строку, чужую не получает.
9. **Откат вставки.** Если транзакция с первым возвратом откатилась, повтор записывает возврат.
10. **Старые правила целы:** сумма > 0, дата не в будущем, не больше оплаченного, участник существует, не администратор (родитель, тренер, локальный администратор) получает `forbidden`.
11. **Права.** `authenticated` выполняет функцию, `anon` нет; проверка на базе с привилегиями по умолчанию Supabase
    (`alter default privileges ... grant ... to anon, authenticated, service_role`). Прямой INSERT/UPDATE/DELETE в `camp_payments` от `authenticated` по-прежнему запрещён.
12. **История.** `request_id` не меняется (UPDATE и DELETE запрещены 0165); существующие строки получают `null`, ничего не объединяется.
13. **preflight и откат.** Строка 0231 в `db/ops/preflight.sql` без `::regclass` по строке и не падает на базе без 0231 (NOT_APPLIED); откат `db/ops/rollback-0231-camp-refund-idempotency.sql`.

## Клиент (экран «Сборы», карточка участника)

14. Один подтверждённый возврат = один ключ. Ключ сохраняется (в памяти страницы, до 30 минут), пока нет успеха; повтор тех же данных после ошибки или потери связи уходит с тем же ключом, другие данные получают новый ключ; после успеха ключ сбрасывается.
15. При `duplicate = true` показывается «Этот возврат уже был записан ранее, второй не создан.», список обновляется.
16. `request id reused` показывается понятным текстом.

## Вне объёма

`camp_pay` и `camp_cancel_payment` (отмена уже защищена уникальностью `legacy_ref`), возвраты экипировки и событий, перенос старых возвратов на ключи, backfill, хранение ключа после перезагрузки страницы.
