# Кнопка «Написать в Telegram» у родителя: ник вместо ссылки по ID (скрин Павла 20.11, решение 21.11)

Условия приёмки. Тесты пишутся от них: `db/tests/rls_parent_tg_username_test.sql` (номера U1-U8), `web/src/lib/tgUsername.test.ts` (A1), `web/src/screens/GroupParentContact.test.tsx` (A2-A4).
Миграция 0218 добавляет колонку и функцию чтения; ник пишет только Edge Function `tg-auth`. Существующие функции (`group_parents`), RLS, права на `users` не меняются. Данные прода не трогаются.

## Что увидел Павел
В карточке игрока («Группа» → игрок → «Родители») кнопка «Написать в Telegram» не работает. Она открывала `tg://user?id=<ID>`: Telegram открывает такую ссылку только для людей из контактов или чатов пользователя, у тренера и администратора родителей там нет. Ника родителя в базе не было.

## Условия приёмки

### База (миграция 0218)
- **U1.** Записи ника из приложения нет: функции `set_my_tg_username` не существует, прямой UPDATE `users.telegram_username` от `authenticated` (своя и чужая строка) и без входа ничего не меняет. Формат ника (4-32 знака, латиница, цифры, `_`, с буквы) защищён ограничением таблицы. Ник пишет только `tg-auth` (service_role) из initData с проверенной подписью, в строку этого Telegram-аккаунта.
- **U2.** `group_parent_usernames(g uuid)` возвращает (telegram_id, username) только для родителей, которых возвращает `group_parents(g)` (то же согласие на контакт тренеру), и только с ником. Вызывать может администратор и тренер этой группы; чужой тренер, родитель, пользователь без входа получают `forbidden`.
- **U3.** Родитель без согласия на показ контакта в результат не попадает (даже с ником).
- **U4.** Прямое чтение `users.telegram_username` чужим пользователем по-прежнему пусто (RLS `users_self` не ослаблена).
- **U5.** Права: `execute` у `group_parent_usernames` у `authenticated`, нет у `anon` и `public`; проверка на базе с привилегиями по умолчанию Supabase.
- **U6.** Строка preflight 0218 есть, на базе без 0218 даёт NOT_APPLIED (через `to_regprocedure` и `information_schema`), на полной APPLIED.
- **U7.** Функция `group_parent_usernames` добавлена в список `rls_definer_hardening_test.sql` (определены осознанно).
- **U8.** `group_parents` не изменена (тест-стражи 0173/0176 остаются зелёными).

### Приложение
- **A1.** При входе через `tg-auth` ник (из подписанных initData, нормализованный) сохраняется сервером; при повторном открытии с живой сессией клиент один раз за открытие отправляет в `tg-auth` подписанные `initData` с `username_only: true` (ник из `initDataUnsafe` не отправляется). Сервер не выдаёт при этом вход и пишет ник только в строку Telegram-аккаунта из подписи, поэтому смена Telegram-аккаунта при старой сессии не может записать ник в чужую строку. Вне Telegram не вызывается. Любая ошибка (миграции ещё нет, сеть) пользователю не показывается.
- **A2.** В карточке игрока у родителя с ником кнопка «Написать в Telegram» ведёт на `https://t.me/<ник>` (внутри Telegram через `openTelegramLink`, иначе обычная ссылка в новой вкладке).
- **A3.** У родителя без ника кнопки нет, под именем подсказка «Ника в Telegram нет. Напишите через администратора клуба.» ID остаётся.
- **A4.** Если функции `group_parent_usernames` в базе ещё нет или она вернула ошибку, экран работает как A3, без ошибки пользователю и без пропажи списка родителей.

## Ограничения (честно)
- Ник подтверждён подписью Telegram (initData проверяются в `tg-auth`), но это ник, который родитель сам выбрал в Telegram; он может смениться, тогда ссылка обновится при следующем открытии.
- Нужен деплой Edge Function `tg-auth` (отдельно от миграции, делает Павел); без деплоя новые ники не появятся, кнопка остаётся подсказкой A3. Функция не проверялась на живом проекте: проверка на staging.
- Ники появятся у родителей по мере их входа или открытия приложения; сразу после применения миграции у всех будет подсказка A3.

## Применение
Миграцию 0218 применяет Павел после свежего `db/ops/preflight.sql`; без неё приложение работает как сегодня (подсказка вместо нерабочей кнопки). Порядок: миграция 0218, затем деплой `tg-auth`.
