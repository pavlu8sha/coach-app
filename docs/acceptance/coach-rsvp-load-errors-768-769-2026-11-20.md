# Матчи с подтверждением (тренер): ошибки загрузки и поиска (#768, #769)

Условия приёмки. Тесты пишутся от них: `web/src/screens/CoachRsvpLoad.test.tsx`.
Экран: `web/src/screens/CoachRsvp.tsx`, карточка матча `RsvpDetail`. Только интерфейс: RLS, grants, SECURITY DEFINER, RPC, миграции и политика `players_read` не меняются. Продуктовая семантика RSVP и доступ тренера не меняются.

## Проблема
- `match_rsvp_summary` при ошибке даёт `null`, `match_rsvp_roster` и `match_activity` — `[]`: сбой выглядит как «Состав пока пуст», пропавшая сводка и «Записей пока нет». Отклонённый Promise в этих запросах не обрабатывается.
- Поиск игроков (`players.ilike`) не смотрит на `error`; ответы могут прийти не по порядку, и старый ответ перезапишет актуальный.

## Условия приёмки

### Загрузка данных карточки (#768)
1. Сводка, состав и история загружаются независимо и имеют отдельные состояния: загрузка, успех, пусто, ошибка. Ошибка одного блока не скрывает и не блокирует успешно загруженные остальные.
2. Ошибка Supabase (`{ error }`) и отклонённый Promise обрабатываются одинаково: блок показывает ошибку («Не удалось загрузить …») с кнопкой «Повторить». Текст понятный, без сырого сообщения базы (через `errMsg`).
3. Ошибка состава не показывает «Состав пока пуст», фильтр ответов и список; «Опубликовать» недоступна, пока состав не загружен. Успешный пустой состав показывает «Состав пока пуст» и без ошибки.
4. Ошибка сводки не показывает карточку сводки с нулями; «Напомнить не ответившим» недоступна, пока сводка не загружена. Успешная сводка показывается как раньше.
5. Ошибка истории не показывает «Записей пока нет»; успешный пустой ответ показывает «Записей пока нет».
6. «Повторить» повторяет только свой запрос; после успеха блок показывает данные, ошибка исчезает.
7. Устаревшие ответы не применяются: при смене матча и при повторной загрузке (после действия или «Повторить») результат более раннего запроса не перезаписывает данные актуального.
8. После действия (отметка, приглашение и т. п.) блоки обновляются; если обновление не удалось, блок показывает ошибку, а не старые данные как актуальные.

### Поиск игроков (#769)
9. Ошибка поиска (`{ error }` и отклонённый Promise) показывает «Не удалось выполнить поиск» с кнопкой «Повторить поиск», а не «ничего не найдено». «Никого не найдено» показывается только при успешном пустом ответе.
10. Результаты показываются, только если они получены для текущего текста запроса. При новом запросе старые результаты не показываются: до ответа «Поиск…». При ошибке нового запроса результаты предыдущего не остаются.
11. Ответы приходят не по порядку: показываются результаты только последнего запроса.
12. «Повторить поиск» повторяет запрос и показывает результаты; поиск короче двух символов ничего не запрашивает и ничего не показывает.
13. Запрос поиска остаётся прежним SELECT `players` под RLS (`ilike`, `limit 8`), без новых RPC.

### Общее
14. Поведение при успехе, тексты кнопок и права прежние; существующие тесты `MatchRsvp.test.tsx` проходят без изменений.
15. Сырой текст ошибки пользователю не показывается (сторожевой тест `noRawErrors.test.ts`).

## Не входит
Ошибка загрузки самого матча (уже есть «Не удалось загрузить матч»); запрос последнего снимка отметок для кнопки «Вернуть отметки до переноса» (при ошибке кнопки нет, как и раньше); политика `players_read` (отдельный вопрос безопасности из #769).
