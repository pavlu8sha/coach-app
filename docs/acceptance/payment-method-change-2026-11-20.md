# Исправление способа оплаты абонемента в «Приёме оплат» (2026-11-20)

Повод: администратор по ошибке выбрал «Перевод», а оплата была наличными. Сейчас в меню «⋯» строки есть только «Отменить оплату».

Решение без миграции: 0179 уже разрешает UPDATE способа оплаты в `payments` (остальные поля неизменяемы) и пишет каждую правку в `audit_log` (`payment_correct`, before/after); RLS `payments_admin` даёт право только администратору.

Условия приёмки:
1. В меню «⋯» строки оплаты абонемента (не отменённой, сумма больше нуля) появляется пункт «Изменить способ оплаты». «Отменить оплату» остаётся.
2. Пункт показывается только при способе ровно «Наличные» или «Перевод» (пустой и устаревшие значения не подменяются, остаётся «Отменить оплату»). Не показывается у отменённой оплаты, у минусовой строки и у оплат не-абонементов (сборы, экипировка, занятия).
3. Окно подтверждения показывает игрока, сумму, текущий и новый способ («Наличные» ↔ «Перевод») и пояснение, что сумма и дата не меняются, правка попадёт в журнал.
4. После подтверждения выполняется ровно один UPDATE `payments` с `method = новый способ` для этой оплаты и условием «текущий способ = прежний» (защита от параллельной правки). Сумма, дата, игрок, месяц не передаются.
5. Если база вернула ошибку или ни одной строки (нет прав, оплату уже изменили или отменили), показывается ошибка «Способ не изменён: …», список перечитывается; успех не показывается.
6. После успеха список перечитывается: итоги «Наличные» и «Перевод» за день пересчитываются, строка показывает новый способ.
7. Если у оплаты уже есть отмена, пункт «Изменить способ оплаты» скрыт: минусовая строка хранит старый способ, и итоги по способам перестали бы сходиться.
8. Повторный клик при выполняющейся операции игнорируется.
Без миграций, SQL и изменения сумм. Проверка на устройстве за владельцем.
