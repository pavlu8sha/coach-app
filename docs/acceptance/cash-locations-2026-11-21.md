# Кассовый отчёт: фильтр локаций по справочнику филиалов и отдельный фильтр «Сборы» (скрин Павла 21.11, решение Павла)

Условия приёмки. Тесты: `web/src/screens/CashReport.test.tsx` (L1-L7), `web/src/lib/branches.test.ts` (L8). Миграций нет; `cash_report` не меняется. Данные прода не трогаются: нормализацию значений делает скрипт `db/ops/normalize-locations-2026-11-21.sql`, его выполняет Павел.

## Что увидел Павел
В списке «Локация» были «Исани» и «Isani» как две локации, а также площадки разовых занятий (35-я школа, Surami Hotel): список собирался из текстовых колонок `groups.location`, `camps.location`, `equipment_orders.location`, `extra_sessions.place`. Филиалов в клубе три: Red Garden, Isani, Ortachala.

## Условия приёмки
- **L1.** Выпадающий список «Локация» берётся из справочника филиалов (`web/src/lib/branches.ts`): «Все локации», Red Garden, Isani, Ortachala. Значения из текстовых колонок в список не попадают, запросов к `groups`, `camps`, `equipment_orders`, `extra_sessions` экран больше не делает.
- **L2.** Выбор филиала передаёт в `cash_report` точное значение справочника (`p_location`), «Все локации» передаёт `null`.
- **L3.** Если в сохранённом состоянии экрана выбрана локация не из справочника (старое значение), она остаётся в списке отдельной строкой, чтобы фильтр не терялся молча.
- **L4.** Новый переключатель «Что показывать»: «Всё», «Сборы», «Без сборов». «Сборы» оставляет операции вида «Сбор», «Без сборов» убирает их. Запрос в базу не меняется.
- **L5.** При «Сборы» и «Без сборов» итог, суммы по способам и по сотрудникам и число операций пересчитываются из показанных операций и сходятся с ними (сумма по способам = сумма по сотрудникам = итог = сумма операций). При «Всё» показываются данные сервера как есть.
  Исключение (решение владельца 2026-11-22): если в `by_staff` у разных `staff_id` одинаковое отображаемое имя, фильтр вида недоступен (показывается «Всё» и пояснение), чтобы суммы сотрудников не склеивались. Полный фильтр потребовал бы `staff_id` в строках `cash_report` (отдельная миграция) и не делается.
- **L6.** Пустой результат фильтра показывает «За период платежей нет», а не пустую страницу; сбой отчёта по-прежнему показывает ошибку.
- **L7.** Разовые площадки (школа, отель) в списке не появляются, но операции с такой локацией остаются видны при «Все локации».
- **L8.** `branchOf(text)` приводит написания к названию филиала справочника: «Исани», «isani», «ისანი» → Isani; «Ортачала», «ortachala» → Ortachala; «Red Garden», «Ред Гарден», «redgarden» → Red Garden; прочее → null. Скрипт нормализации использует тот же перечень написаний.

## Нормализация данных (скрипт, выполняет Павел)
`db/ops/normalize-locations-2026-11-21.sql`: шаг 1 только чтение (какие значения где есть и на что будут заменены); шаг 2 одной транзакцией приводит написания филиалов к названию справочника в `groups.location`, `equipment_orders.location`, `extra_sessions.place` и `location_admins.location` (по ней работают права администраторов локаций, поэтому меняется вместе с остальными), со сверкой числа строк; значения не из перечня (разовые площадки, сборы) не меняются. `camps.location` не меняется (место сбора, а не филиал).

## Не входит
Серверный фильтр по виду операции (итоги пересчитываются на экране); справочник филиалов в базе (пока константа).
