# Смена способа оплаты абонемента через функцию (0216, 2026-11-20)

Повод: «Изменить способ оплаты» из #781 не сработала в проде. Причина: у роли `authenticated` на `payments` отозвано право UPDATE (0004: `revoke update, delete on payments from authenticated`), а RLS-политика права на таблицу не возвращает. 0179 разрешает менять `method` триггером, но не выдаёт привилегию. Тест на fake это не показал.

Решение: функция `payment_set_method(pid uuid, new_method text, old_method text) returns jsonb`, `security definer`. Права на таблицу не меняются (журнал по-прежнему только добавляется для обычных ролей).

Условия приёмки:
1. Вызывает только администратор (`is_admin()`); тренер, родитель и anon получают `forbidden` (42501); EXECUTE у anon и public отозван, у authenticated выдан.
2. Прямой `update payments set method = ...` от authenticated (администратор) по-прежнему отклоняется базой: права на таблицу не расширены.
3. Допустимые значения только «Наличные» и «Перевод» (иначе 22023); платёж должен существовать (иначе P0002), быть положительным и не отменённым (на него нет записи с `cancels`) (иначе 22023).
4. `old_method` защищает от параллельной правки: если текущий способ не равен `old_method`, ошибка 40001 «payment changed», запись не меняется.
5. Меняется только `method`: сумма, дата, игрок, месяц, автор остаются прежними; другие платежи не затрагиваются.
6. Каждая правка пишется в `audit_log` (`payment_correct`, before/after) триггером 0179; если триггера нет (0179 не применена), функция отказывает ошибкой, а не правит молча без журнала.
7. Повтор на уже нужный способ (`new_method` равен текущему и `old_method` тоже) ничего не меняет и ответ `changed:false`.
8. Экран «Приём оплат» зовёт `payment_set_method` через `rpc`, а не прямой UPDATE; сообщение об ошибке понятное: нет прав, оплата уже изменена/отменена, «правка не установлена в базе» при отсутствии функции или 0179.
9. Проверка прав на базе с привилегиями по умолчанию Supabase (`alter default privileges ... grant ... to anon, authenticated, service_role`) и без них.
Деньги, суммы и расчёт долга не меняются. Применяет Павел после `db/ops/preflight.sql`; откат: `db/ops/rollback-0216-payment-set-method.sql`.
