# Оплата за визит: дозаполнение визитов при смене режима (миграция 0213)

Условия приёмки. Тесты в `db/tests/rls_own_visits_backfill_test.sql` пишутся от этих условий. Решение владельца 2026-11-20: если игрок «за визит» был на тренировке, нужен визит за плату (20 ₾); миграцию делать.
Отменяет для этого случая условие 2 из `PAY_PER_VISIT_ACCEPTANCE.md` («смена настройки не меняет прошлые строки»): теперь смена режима создаёт недостающие визиты за уже отмеченные занятия.

1. **Дозаполнение.** `player_set_pay_mode(p, 'per_visit', from)` создаёт неоплаченные строки `own_visits` (сумма `own_visit.fee`) за занятия с отметкой «Был», дата которых от `from` до сегодня включительно (по Тбилиси), если строки визита ещё нет.
2. Занятия раньше `from`, занятия с «Не был» и будущие занятия визита не получают.
3. Существующие строки, в том числе оплаченные, не меняются: сумма, оплата и платежи остаются. Повторный вызов с теми же данными ничего не дублирует.
4. Повторное сохранение того же режима и той же даты тоже дозаполняет (так исправляют уже переведённых игроков).
5. Перевод на «Абонемент» ничего не создаёт и не удаляет. Игроки с абонементом визитов не получают.
6. `payments`, `subscriptions` и `service_payments` не меняются.
7. `own_visits_backfill` недоступна ролям `authenticated`, `anon`, `public` (проверка на базе с привилегиями по умолчанию Supabase). `player_set_pay_mode` по-прежнему только для администратора.
8. Данные: для уже переведённых игроков (Fedorov Matvey, Fedorov Lev) после применения миграции дозаполнение запускает админ повторным сохранением карточки или скриптом `db/ops/backfill-own-visits-2026-11-20.sql`.

Откат: `db/ops/rollback-0213-own-visits-backfill.sql`. Применяет только Павел после `db/ops/preflight.sql`.
