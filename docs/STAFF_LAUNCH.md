## 3. Подготовка людей (один раз)
1. Администратор входит в приложение из Telegram (получает запись в `users`). Права админа выдаёт владелец запросом из `docs/OWNER_CHECKLIST.md`.
2. Каждый тренер входит из Telegram, выбирает роль «Тренер». Администратор в «Ещё → Тренеры» назначает ему группы.
3. Проверить вход из браузера (виджет Telegram) для тех, кто работает с компьютера: `docs/OWNER_CHECKLIST.md`.
4. Включить уведомления бота (секрет, деплой, расписание): `docs/NOTIFICATIONS.md`.

## 4. Перед переходом каждого раздела
1. Свежий импорт и `verify.mjs`: расхождений нет (`docs/SYNC_PLAN.md`).
2. Пробного дня нет (решение 2026-10-29); вместо него проверка без записи в пятницу и сверка `verify.mjs` после импорта.
3. Дата «с этого дня ведём в новом»: импорт раздела выключается, старое приложение для него — «только чтение».
4. Порядок разделов изменён решением 2026-10-29: все разделы (тренеры и администраторы) переходят одновременно 01.11 после одного финального импорта в сб 31.10; поэтапного перехода и пробного дня нет.

## 6. Проверка «всё работает» после слияния и миграций (15 минут)
Администратор: открыть «Занятия» → отметить тестовое занятие; «Оплаты за месяц» → выбрать группу → внести платёж −/+ (исправлением вернуть); «Должники» → списать и вернуть; «Индивидуальные» → создать занятие → записать → отметить оплату → удалить после отмены; «Экипировка» → новый заказ → платёж → выдача; «Сборы» → открыть сбор; «Учёт тренеров» → день → «Проведена». Тренер: свои группы видны, чужие нет; «Матчи» → внести счёт; «Статистика». Любая ошибка вида «миграция ещё не установлена» означает, что пропущена соответствующая миграция.
