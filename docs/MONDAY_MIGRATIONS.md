# Применение миграций 0028–0044 (памятка на понедельник)

Миграции применяет владелец в Supabase: SQL Editor, по одной, **по номерам**. Файлы лежат в `db/migrations/`. Эта памятка проверена на локальной копии: все 15 файлов подряд встают без ошибок, тесты доступа проходят.

## 0. Перед началом
1. Обновить репозиторий: `git pull` (PowerShell, папка проекта).
2. Сделать резервную копию: Supabase, Database → Backups (или Project Settings → Database → скачать). Если проект на бесплатном тарифе без копий, выгрузить хотя бы таблицы `users`, `player_guardians`, `payments`, `subscriptions`, `point_events` в CSV (Table Editor → Export).
3. Выбрать время без работы людей: во время миграций приложение может отвечать ошибками. Хватит 15–20 минут.

## 1. Что уже применено
Открыть SQL Editor, вставить содержимое `db/ops/preflight.sql`, выполнить. В таблице `applied = true` — миграция уже есть, **её применять не нужно** (повторный запуск упадёт на `create table` или `create trigger`). Применять нужно только строки с `false`, по возрастанию номера.

## 2. Применение

### Быстрый путь: один файл
Если `preflight.sql` показал `applied = false` для всех номеров от 0028 до 0044 (ни одна ещё не применена), откройте `db/ops/apply_all.sql`, скопируйте всё, вставьте в SQL Editor и запустите один раз. Файл уже обёрнут в `begin; … commit;`: при любой ошибке не применится ничего, пришлите текст ошибки. Если часть номеров уже применена, соберите файл от первого неприменённого номера: `scripts/make-apply-bundle.sh 0035 > db/ops/apply_all.sql` (или попросите меня). Проверено на чистой базе после 0027: все миграции встают без ошибок, `preflight.sql` показывает `true`.

### По одной
Для каждой миграции с `applied = false`, по номеру:
1. Открыть файл `db/migrations/00NN_….sql`, скопировать всё содержимое.
2. В SQL Editor вставить: `begin;` в первой строке, затем содержимое, затем `commit;` в последней. Тогда при ошибке ничего не применится наполовину.
3. Выполнить. Ожидается «Success. No rows returned».
4. Следующий номер.

Что делает каждая миграция:

| № | Что даёт |
|---|---|
| 0028 | Вход ребёнка по коду от родителя |
| 0029 | Криптостойкий код ребёнка, лимит попыток |
| 0030 | Закрывает лишний доступ к служебной функции |
| 0031 | Уведомления: оплата и баллы родителю, группа тренеру |
| 0032 | «Списать долг» и «Создать абонементы на месяц» |
| 0033 | Статистика посещаемости и матчей |
| 0034 | Индивидуальные и вратарские |
| 0035 | Дополнительные тренировки |
| 0036 | Экипировка |
| 0037 | Сборы |
| 0038 | Учёт тренеров |
| 0039 | Заявки из бота «Хочу в KickStart» |
| 0040 | Старт подсчёта баллов |
| 0041 | Фильтр «Турнир» на экране «Матчи» у родителя (названия турниров без взносов) |
| 0042 | Тренеры видят и ведут все группы; просмотр посещаемости тренеров |
| 0043 | Штат матча (тренер, оператор) и статистика тренеров |
| 0044 | Заявка на пробную из приложения (форма в «О клубе») |

## 3. Проверка
1. Выполнить `db/ops/postcheck.sql`. Строки отсортированы так, что неудачные идут первыми. **Все строки должны быть `ok = true`.**
2. Выполнить `db/ops/preflight.sql` ещё раз: везде `true`.
3. Открыть приложение администратором и пройти проверку на 15 минут из `docs/STAFF_LAUNCH.md`, раздел 6.
4. Если приложение пишет «миграция ещё не установлена» — пропущен соответствующий номер из таблицы выше.

## 4. Если миграция упала
- Если вы обернули в `begin;` … `commit;`, ничего не применилось: прочитать текст ошибки, **не запускать дальше**, прислать мне текст ошибки (секреты не присылать), я исправлю.
- Если запустили без `begin;` и часть выполнилась, снова выполнить `preflight.sql`: он покажет, что уже есть. Повторно файл целиком не запускать, прислать ошибку.
- Откат: данных миграции не удаляют (только добавляют таблицы, колонки и функции; в 0040 историю баллов можно вернуть, сняв дату). Чтобы вернуть состояние до, восстановите резервную копию.

## 5. После миграций (по порядку)
1. Включить уведомления: `docs/NOTIFICATIONS.md` (секрет, деплой `tg-notify`, расписание).
2. Заявки из бота — только после юридической проверки текста согласия: `supabase/functions/tg-bot/README.md`.
3. В день запуска для родителей: «Ещё → Старт подсчёта баллов» → дата этого дня.
4. Ввести администратора и тренеров, назначить группы: `docs/STAFF_LAUNCH.md`, раздел 3.
