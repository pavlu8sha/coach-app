# Уведомления в Telegram (2026-10-23)

Бот присылает сообщение о важных событиях. Это **очередь в базе** (миграция `0026_notifications.sql`) и **функция-отправитель** `supabase/functions/tg-notify`, которую по расписанию вызывает планировщик.

## О чём уведомляем

| Кому | Событие |
|---|---|
| Администратору | новый запрос на привязку ребёнка (и повторный запрос после отказа) |
| Администратору | запрос родителя на удаление данных (после миграции 0025) |
| Родителю | запрос на привязку подтверждён или отклонён |
| Родителю | запрос на удаление данных выполнен или отклонён (с причиной) |

Текст сообщения готовит база при самом событии (триггеры; существующие функции не менялись). В сообщение попадает имя ребёнка и группа: получатель и так видит их в приложении. Кнопка «Открыть приложение» ведёт в Mini App.

## Как это работает

1. Триггер на `link_requests` / `data_requests` кладёт строку в `notifications` (если получатель не отключил уведомления: `users.notifications_enabled`).
2. Раз в минуту планировщик вызывает `tg-notify` с секретным заголовком. Функция забирает до 20 сообщений (`claim_notifications`: забранное закрепляется на 2 минуты, чтобы параллельные запуски не отправили одно и то же), отправляет через Bot API и отмечает итог (`finish_notification`).
3. Временные ошибки повторяются (до 3 попыток). Если пользователь заблокировал бота или никогда его не запускал (ответ Telegram 403 / «chat not found»), сообщение закрывается без повторов. Отправленные старше 30 дней удаляются.
4. Родитель отключает уведомления переключателем в профиле.

## Что должен сделать владелец (один раз, после слияния PR и применения миграции)

1. **Секрет:** придумать случайную строку и записать в секреты функции (в чат не присылать):
   `npx.cmd supabase@latest secrets set NOTIFY_SECRET=<строка> --project-ref ypxbwhjsqkrciozdhajf`
2. **Деплой функции:**
   `npx.cmd supabase@latest functions deploy tg-notify --no-verify-jwt --project-ref ypxbwhjsqkrciozdhajf`
3. **Расписание.** В Supabase: Database → Extensions → включить `pg_cron` и `pg_net`. Затем в SQL Editor (вместо `<СТРОКА>` подставить ту же строку, что в п. 1):
   ```sql
   select cron.schedule('tg-notify', '* * * * *', $$
     select net.http_post(
       url := 'https://ypxbwhjsqkrciozdhajf.supabase.co/functions/v1/tg-notify',
       headers := jsonb_build_object('Content-Type', 'application/json', 'x-notify-secret', '<СТРОКА>'),
       body := '{}'::jsonb
     )
   $$);
   ```
   Остановить рассылку: `select cron.unschedule('tg-notify');`.
4. Проверить: подать запрос на привязку тестовым родителем — администратору должно прийти сообщение в течение минуты.

## Ограничения

- Бот может писать только тем, кто хотя бы раз запускал его (кнопка «Старт» в чате). Остальным сообщение не доставится (закроется без повторов, в очереди останется причина `last_error`).
- Переключатель уведомлений есть только в профиле **родителя**. У администратора и тренера профиля в приложении нет: отключить им уведомления можно только в базе (`update users set notifications_enabled = false where …`).
- Тренерам уведомления пока не отправляются (нет событий, которые нужно им доставлять).
- Если на проекте нельзя включить `pg_cron`/`pg_net`, сообщения копятся в очереди, а приложение работает как раньше. Тогда отправителя можно запускать другим планировщиком, вызывая тот же URL с тем же заголовком.
- Если очередь забита неотправляемыми сообщениями, их видно запросом: `select state, count(*) from notifications group by 1;`.
