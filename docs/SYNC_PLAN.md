# Данные, пока разделы ведут в старом приложении (2026-10-24; с 01.11 повторных импортов нет, см. CUTOVER_ADMINS.md)

Сейчас тренеры и администратор ведут всё в старом приложении (Google Таблицы), поэтому **хозяин данных — таблицы**, а база отстаёт. Новое приложение для родителей показывает то, что попало в базу, поэтому базу нужно регулярно обновлять из таблиц.

## Принцип: у каждого раздела один хозяин
- **Пока раздел ведут в старом приложении** — база обновляется из таблиц скриптами импорта. В новом приложении этот раздел не правят (правки будут затёрты следующим импортом).
- **Когда раздел переходит в новое приложение** — импорт этого раздела выключается навсегда, старое приложение для него переводится в «только чтение».
- Данные, которых нет в таблицах, импорт не трогает: привязки и согласия родителей, коды ребёнка, уведомления, заявки из бота, баллы от тренеров, матчи и занятия, созданные в новом приложении (у них нет внешнего ключа импорта).

## Как обновлять (сейчас — вручную, владелец)
1. Выгрузить листы в CSV и папки (как в `scripts/import/README.md`).
2. Прогнать скрипты **в этом порядке** (каждый сначала без `--write`, смотреть отчёт, потом с `--write`):
   `run-players` → `run-birth` → `run-schedule-log` → `run-attendance` → `run-payments` → `run-individual` → `run-equipment` → `run-camps-settings` → `run-events` → `run-rating` (только баллы за тренировки) → кнопка «Пересчёт баллов за матчи» в приложении («Ещё»).
3. Запустить `verify.mjs`: он покажет, где база расходится с таблицами.
4. Раз в сутки достаточно; перед важным (сбор оплат, рассылка долга) — сразу перед ним.

Повторный запуск безопасен: скрипты пишут «слиянием» по внешним ключам и не плодят дубли.

## Что скрипты не умеют (знать заранее)
| Раздел | Ограничение |
|---|---|
| Оплаты | Новые платежи добавляются один раз (по `legacy_ref`). Если в таблице платёж **исправили или удалили**, база этого не узнает; расхождение покажет `verify.mjs`, исправлять придётся вручную (запись с минусом в приложении). Даты платежа в выгрузке нет: все платежи ставятся на 1-е число месяца |
| Игроки | Импорт перезаписывает имя, группу, статус и дату рождения импортированных игроков. Не правьте их в новом приложении до перехода раздела |
| Индивидуальные, экипировка, сборы | Записи импортированных занятий и заказов перезаписываются; правки в новом приложении будут затёрты |
| Баллы за матчи | **Импорт баллов за матчи отключён** (флаг `--with-matches` только для пустой базы): после миграции 0027 баллы за матчи считает база, а старая схема дала бы вторые начисления. Для этого раздела — кнопка «Пересчёт баллов за матчи» |
| Выдача экипировки, «списано» у должников | Эти данные есть только в новом приложении и импортом не затрагиваются; в старом приложении они живут отдельно |

## Что можно улучшить (нужно ваше решение)
1. **Автоматический импорт раз в час** (GitHub Actions + чтение Google Таблиц сервисным аккаунтом). Даёт боевой ключ записи автоматическому процессу, поэтому решаете вы. Объём — 2–3 дня.
2. **Подпись «Данные на … число»** в приложении для родителей: честно показывает возраст данных. Объём — полдня.
3. **Порядок перехода разделов** (предложение): сначала посещаемость и матчи у тренеров (в новом приложении уже готовы, самое частое действие), затем оплаты и долги у администратора, затем индивидуальные, экипировка, сборы, учёт тренеров. По каждому разделу фиксируем дату «с этого дня ведём в новом», выключаем импорт и ставим старому «только чтение».
