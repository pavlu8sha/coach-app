## 4. Детали подтверждений

### R-01. Баллы и посещаемость чужой группы

Последовательность:

1. Тренеру U9 назначена только группа U9.
2. Вызывается `mark_attendance(<занятие U11>, '[{"player_id":"<игрок U11>","status":"present"}]')`.
3. Ожидается `42501`, фактически появляются `attendance` и `point_events` для U11.
4. Аналогично `save_match(null, <U11>, ...)` проходит проверку `is_any_coach()` и применяет баллы матча.

Проверка `players_read`/`attendance_read` после `0042` также даёт тренеру доступ ко всем группам, но это соответствует решению владельца «все группы». Нарушение именно в **записи** баллов/посещаемости: решение прямо говорит «начислять можно только своим».

### R-02. `export_my_data` и `points_start`

Проверено в одной транзакции: до `points_start` у ребёнка есть балл `5`. Прямой `select` из `point_events` под родителем даёт `visible_points=0`, а `jsonb_array_length(export_my_data()->'points')` даёт `1`. RLS на `point_events` не применяется внутри `security definer` функции, а в `0025:37` нет фильтра по `occurred_on`.

### R-03. Настройка долга родителям

`Debtors.tsx:84`:

```ts
supabase.from('club_settings').upsert(
  { club_id: clubId, key: 'parent_debt_enabled', value: enabled ? 'false' : 'true' },
  { onConflict: 'club_id,key' },
)
```

Схема:

```sql
primary key (club_id, key, scope)
```

Ошибка PostgreSQL:

```text
42P10: there is no unique or exclusion constraint matching the ON CONFLICT specification
```

Функционально настройка «Показ долга родителям» не переключается. Исправление напрашивается в `onConflict: 'club_id,key,scope'` либо в явном `scope: ''`; в рамках аудита не применялось.

### R-05. Гонка лимита индивидуальных

Два параллельных вызова `ind_book` для разных игроков и одного занятия с cap=1. Первый вызов задерживался тестовым триггером `pg_sleep(3)` после проверки. Оба прошли `n >= cap`, оба вставили бронь. После отката тестовый триггер удалён; в рабочую схему не добавлялся.

### R-10/R-11/R-12. Учёт тренеров

- `tl_confirm` возвращает `0`, если хотя бы одна строка уже `held`; остальные тренеры не добавляются.
- Дублирующийся массив тренеров создаёт дубли строк: ключ `external_id` строится с суффиксом, уникальность по тренеру не enforced.
- `tl_set_held` не содержит проверки `held_on <= today`, в отличие от `tl_add`/`tl_confirm`.

### R-14/R-15. Черновик заявки

- `leadStep(cb('lead_yes'), draft={step:'confirm', ...})` возвращает `draft:null`; обработчик `index.ts` в ветке `else` удаляет `lead_drafts`.
- 30-дневный черновик не удаляется, пока не будет успешно создана новая заявка. При дубликате `lead_submit` выходит на `:40` до cleanup, поэтому черновик остаётся и снова читается.

### R-16. Уведомление о скрытых баллах

`notify_bonus` срабатывает на `source_type='coach' and points > 0` и не смотрит на дату. Подтверждено: балл от 2026-09-01 при `points_start=2026-10-01` создаёт 1 запись `notifications(kind='bonus')`.

### R-17. Устаревшие ответы web

Во всех трёх экранах запрос идёт в `useEffect`, а результат без проверки актуального ключа вызывает `setState`:

- `MonthPayments`: старый `gid`/`month` может перезаписать `players`, `paid`, `subs`; последующая оплата использует новый `month` со старым игроком.
- `Debtors`: старый `month` может перезаписать `rows`; скидка/списание применяются к новому месяцу.
- `TrainerLog`: старый `date` может перезаписать `slots`/`logs`; подтверждение уходит на новую дату со старыми строками.

## 5. Что проверено и признано корректным

### 3.1. Границы значений и админ-сценарии

- `ind_book` отклоняет игрока другого клуба, повторную бронь и полностью оплаченное занятие; проверка вместимости корректна последовательно, дефект только в гонке R-05.
- `eq_create_order`/`eq_edit_order` защищают `total` от отрицательного значения и от уменьшения ниже `paid`; `eq_add_payment` не даёт уйти в минус и превысить сумму. Ранее выглядевшее подозрительным отрицательное `custom_total` **не является дефектом**: при `paid=0` его отсекает проверка `new_total < paid`.
- `camp_pay`/`camp_cancel_payment` не дают отрицательную оплату и не позволяют отменой уйти ниже нуля.
- `create_subscription_month` идемпотентна; повторный вызов не создаёт дубли.
- `extra_set_attended`/`extra_set_paid` проверяют существование брони; дефект только в знаке суммы R-07.

### 3.2. Доступ и роли

- `lead_submit` доступна только `service_role`; `lead_drafts` недоступна приложению; `equipment_issues` читается родителем только по своему ребёнку.
- `camp_*` read-пути закрыты для чужих родителей; `points_start`/`set_points_start` — только админ.
- `attendance_stats`/`match_stats` отклоняют родителя; тренер видит все группы клуба по решению владельца. Cross-club R-04 — отдельное ограничение multi-club.
- `link_requests`, `child_codes`, `rate_limits` не проверялись исчерпывающе: это зона #144, отдельно не дублировалась.

### 3.3. Целостность

- `camp_cancel_payment` не допускает отрицательный баланс; `eq_edit_order`/`eq_add_payment` защищают оплату; `tl_add`/`tl_confirm` не принимают будущую дату для `held` (кроме обходного `tl_set_held` R-12).
- `debtors`/`parent_debts` после списания и скидки ведут себя согласно `docs/DEBT_RULES.md`; настройка видимости долга сломана только на web-пути R-03.

### 3.4. `points_start`

- Прямой RLS, `group_rating`, `parent_debts`, `attendance_stats` не показывают старые баллы.
- Проблемы только в `export_my_data` R-02 и `notify_bonus` R-16.

### 3.5. Бот и leads

- `lead-logic.js` валидирует имя, год и телефон, нормализует телефон и экранирует пользовательский текст; `parse_mode` не задаётся, поэтому HTML/Markdown-инъекция через имя/телефон не воспроизводится.
- `contact` и ссылки формируются из контролируемых шаблонов; пользовательские значения не подставляются в URL.
- Черновики и stale callback имеют дефекты R-14/R-15; телефон из пробелов — R-13.
- Не проверено runtime: отсутствует Deno и реальный Telegram webhook.

### 3.6. Web

- XSS через React-экраны не найден: имена/комментарии выводятся как текст, `tel:`/`https://t.me/` формируются из допустимых схем, `dangerouslySetInnerHTML` не используется.
- Роли не обходятся на UI-уровне: скрытые кнопки не являются единственной защитой, серверные RPC проверяют права.
- Мелкие замечания без отдельного дефекта: отсутствует `catch` у clipboard в `Camps.tsx`; `PointsStart.tsx` не показывает ошибку загрузки; в `Leads.tsx` вложенная кнопка внутри кликабельной строки; поиск оборудования включает неактивных игроков.
