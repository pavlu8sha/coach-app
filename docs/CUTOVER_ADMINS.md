# Переход администраторов на новое приложение: 01.11.2026

Решение владельца (подтверждено 2026-10-29): **с воскресенья 01.11 и тренеры, и администраторы работают только в новом приложении.** Параллельного периода и повторных импортов нет. Прежний ориентир 15.11 отменён.

Следствие: сб 31.10 вечером делается **один полный финальный импорт** (`final-import.mjs --mode Final`: игроки, посещаемость, матчи, оплаты, индивидуальные, дополнительные, экипировка, сборы, баллы), затем старое приложение закрывается для записи (окно `MAINT_UNTIL`, только чтение). Режим Daily после 01.11 не используется. Пошагово: `docs/SATURDAY_IMPORT_CHECKLIST.md`.

## До субботы: условия «можно переходить»
- Все админы (Дима и клубный аккаунт) вошли в новое приложение, `is_admin` стоит.
- Нет открытых ошибок по оплатам, должникам, индивидуальным, допам, экипировке, сборам (в первую очередь #247, #277).
- Проверено на телефоне, ноутбуке и iPad (боковое меню с ширины 1100 px).
- Админы заранее посмотрели новое на чтение: должники, «Приём оплат», карточка игрока.

## Суббота 31.10, вечер: финальный импорт
1. Остановить ввод в старом, выгрузка с `MAINT_UNTIL`; копия таблиц (`db/ops/snapshot_before_import.sql`).
2. Final без записи, затем с `--write`, `verify.mjs`, при необходимости `quality.mjs`. Сверка денег: оплаты, экипировка, сборы, индивидуальные — **расхождений нет**.
3. Итоги старого приложения на 31.10 (сумма оплат за месяц, должники, оплаченная экипировка) записать для воскресной сверки.
4. Если сверка не сошлась: старое остаётся рабочим (снять `MAINT_UNTIL`), переход переносится; тренеры в этом случае тоже не переходят.

## Воскресенье 01.11: переход
- Админы вносят оплаты, экипировку, сборы, индивидуальные только в новом. Старое открыто только для чтения.
- Вечером: платежи за день (экран «Приём оплат»), должники, `db/ops/trainer_day.sql` по тренерам; сверка с ожиданиями админов и с итогами старого на 31.10.

## Откат
- До начала работы в новом (до утра воскресенья): снять `MAINT_UNTIL`, вернуться в старое, импорт повторить после исправления.
- После первых записей в новом возврата к старому без потери данных нет: внесённое в новом приложении переносить в таблицы вручную по журналу платежей. Всю базу из Backups не восстанавливать. Исправлять вперёд, точечно, с разработчиком; копии таблиц в схеме `snap_20261031`.

## После перехода
- Через неделю: смена `APP_PIN` и `APP_ADMIN_PIN` в старом, отключение записи.
- Родители: отвязать тестовую привязку ребёнка владельца, задать «Старт подсчёта баллов», юридическая проверка согласия, затем `LEADS_ENABLED=1`.
- Заявки из бота заменяют воронку «Новые игроки», переносить её не нужно.
